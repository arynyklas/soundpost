# Soundpost v1 module and protocol contracts

Date: 2026-11-03. **Approved by Aryn Yklas for implementation with m1 implementers and m2 reviewers.** These are binding implementation contracts, not implemented-capability claims. [Design](2026-11-03-soundpost-design.md) and [requirements](2026-11-03-soundpost-requirements.md) govern. Paths below are planned until implemented and verified. Copyright 2026 Aryn Yklas. All first-party files are Apache-2.0. Soundpost owns its protocol/model; only PromQL/LogQL language semantics intentionally match upstream profiles.

Stateful modules use explicit receivers with dependencies injected through consumer-owned narrow interfaces; free functions below describe call arguments, not global singletons. Pure reducers/codecs stay free functions. `internal/model` is a leaf shared-types package. Ingest consumes an `Appender` interface without importing storage; storage may implement that interface. Query consumes a `Scanner` interface; rules consume query/control output interfaces. Control stores leaf DTOs and never imports feature implementations. Concrete cross-module adapters/wiring live in `internal/app`; this prevents Go import cycles while retaining the declared call contracts.

## C01. Shared identities, time and errors

Planned `internal/model/identity.go`: `type ID [16]byte`, `type SpanID [8]byte`, `type UnixNano int64`, `type MonoNano uint64`, `type Revision uint64`, `type Cursor struct { Group ID; Index uint64 }`. Wire ID is lowercase 32-hex (span 16-hex), no all-zero value. Wire nanoseconds/uint64 are canonical decimal strings; no JSON-number roundtrip. Unix time is signed int64 nanoseconds; monotonic domains have explicit host/boot/runtime identity. Trace clocks use `{wall_ns,mono_ns,domain,uncertainty_ns}` and never subtract unlike monotonic domains.

Planned `internal/model/errors.go`: `type Code string` enumerates `invalid`, `unauthenticated`, `forbidden`, `conflict`, `too_large`, `unsupported`, `quota`, `unavailable`, `timeout`, `cancelled`, `stale`, `not_found`, `corrupt`. `type Fault struct { Code Code; Retryable bool; SafeDetail string; RequestID ID }` implements `error`. Public failures contain code/request ID and approved detail only; no body echoes, raw query/credential dumps or filesystem paths. Wrong-scope IDs look like not-found; authentication/authorization failures are independent of object existence.

`internal/model/value.go` declares `type FloatBits uint64` with exact hex wire form (16 lowercase hex digits). Ordinary NaN payload and stale `0x7ff0000000000002` are distinct. Native histogram is a tagged `IntegerHistogram|FloatHistogram` union. Both retain flavor, schema, zero threshold, sum bits, spans, reset hint and optional custom bounds. Integer count/zero-count/absolute bucket counts use decimal uint64 strings; integer delta buckets use decimal int64 strings; float counts/buckets use FloatBits. Counts above 2^53 are never routed through float64 at admission. Schema-specific count/span validation precedes ACK; the evaluator converts only when the reference profile requires conversion. `Labels` is a sorted unique-name list, not a map with duplicate-key ambiguity. Missing labels remain distinct from present empty labels at storage level.

## C02. Authorization seam

`internal/auth/scope.go` owns an opaque `type Scope struct` with unexported principal/org/project grants, permissions, policy epoch, elevation audit ID and deadline. Constructors are confined to this package. `Authorize(ctx context.Context, credential Credential, org model.ID, projects []model.ID, action Permission) (Scope,error)` checks current control-group state. `Revalidate(ctx context.Context, scope Scope) error` fences revocation/deletion. `Scope` is not JSON-deserializable and has no caller-settable wildcard.

A `Credential` is a validated session/server token; only HTTP auth parses raw headers. Internal workers obtain scoped service principals. Every interface requires Scope or validated SourceGrant. Scope includes an authorization-generated `VisibilityFingerprint` covering principal identity and all effective project/action/named restricted-source reader grants. Caches key `(org,visibility_fingerprint,policy epoch,delete generation,profile,query,time params)`; reusable pagination/live replay/export state has the same binding. Shared org epoch/project actions alone cannot equate two users with different raw-source grants. ReadIndex revalidation precedes response/chunk release; long compute has a 5-second maximum lease. No content-address-only artifact cache, caller wildcard or post-revocation chunk is allowed.

`internal/auth/elevation.go`: `Elevate(ctx, session Session, reason string, orgs []model.ID) (Elevation,error)` requires fresh reauthentication and an already committed audit ID; elevation expires at 15 minutes. Read audit is committed before elevated result release. Local bootstrap is a random one-time admin token printed only to the console/0600 bootstrap file; production has no default password. Destination/source secrets use AES-256-GCM envelope keys from a local 0600 key file or configured KMS; backups encrypt keys separately, rotate with key IDs and never log plaintext.

`internal/auth/service.go` owns injected `Service`/`NewService(deps AuthDependencies)(*Service,error)`; dependencies are narrow control/key/clock/session stores. `internal/httpapi/session.go` owns `RegisterSessionRoutes(mux *http.ServeMux,service *auth.Service)`. UI consumes those real routes, not a duplicate auth backend. Named restricted-source reads require `raw.read` plus the specific source-reader grant.

## C03. Ingest and durable append

Planned `internal/ingest/types.go`:

```go
type Batch struct {
    Version uint16
    Project model.ID
    Source model.ID
    Producer model.ID
    ID model.ID
    PolicyRevision model.Revision
    RouteSlot uint16
    Records []Record
}
type Record struct {
    ID model.ID
    Kind Kind
    ObservedAt model.UnixNano
    Resource Resource
    Payload Payload
}
type Receipt struct {
    BatchID model.ID
    Hash [32]byte
    Cursor model.Cursor
    RetainUntil model.UnixNano
    SignalDeadlines []SignalDeadline
    DedupUntil model.UnixNano
}
```

`Kind` is a closed enumeration: `metric`, `log`, `span`, `error`, `job_attempt`, `replay_chunk`, `profile_chunk`, `capability`, `loss`, `condition`. `Payload` is a closed tagged union of the types in C04; mismatched tags, arbitrary `map[string]any` payloads and unknown kinds are rejected. `Resource` is registered service ID, environment ID, build ID, instance pseudonym and approved labels. Project/source comes from validated source credential; body values must match, never select another tenant.

Shared Kind and telemetry Payload definitions are leaf `internal/model` types; ingest aliases them for its protocol surface, preventing model→ingest→storage/control cycles. Exact admitted float/integer histogram forms follow C01, not an opaque map.

`internal/policy/source.go`: `ResolveSource(ctx, credential SourceCredential, project,source model.ID, revision model.Revision) (SourceGrant,error)` returns an opaque grant with policy/class/quota and deadline. Control ReadIndex and the C12 data-group barrier jointly fence policy changes; ReadIndex alone is not a cross-group transaction. `Normalize(grant SourceGrant, input Batch) (NormalizedBatch,error)` drops unknown optional fields, validates registered template fields and creates a canonical deterministic encoding. It never mutates caller-owned SDK state and never stores rejected raw bytes.

`internal/ingest/service.go`: `Admit(ctx context.Context, grant SourceGrant, batch Batch) (Receipt,error)`. `internal/storage/group.go`: `(*Engine).Append(ctx context.Context, scope auth.Scope, batch NormalizedBatch) (Receipt,error)`. Ingest obtains its scope from the validated grant. Each normalized batch includes canonical hash, source-policy epoch/hash, per-record admission/retention times, durable quota-reservation token and route slot. Dedup key is `(org,project,source,producer,route_slot,batch)` for 7 days; changed content is conflict. `SignalDeadline{Kind,RetainUntil}` is declared in ingest/types.go; receipt `RetainUntil` is the minimum of those deadlines, not a promise all records disappear together. Original receipt including deadlines is returned on retries even if some/all data has expired or been deleted; receipt lookup does not resurrect it.

Historical receipt lookup is not new admission. `internal/ingest/receipts.go` owns `LookupReceipt(ctx,credential SourceCredential,request ReceiptRequest)(Receipt,error)` and `ReceiptRequest{Source,Producer,RouteSlot,BatchID,OriginalHash}`; own `POST /ingest/v1/receipts` authenticates the current source credential and checks nonretired org/project plus source ownership. Invalid/revoked credentials receive401/403 and are explicitly outside retry guarantees. A still-authorized source may retrieve the original receipt after restrictive policy, historical data deletion or expiry without normalization, reservation or append; the response marks `historical:true`, not a new successful write. SDK uses this after ambiguous response before a new-admission retry. Lookup does not resurrect data, disclose record values or permit retired scopes. Same BatchID/different OriginalHash is conflict. An old policy cannot mutate committed bytes merely to manufacture a hash mismatch.

Routing v1 has 64 fixed virtual slots, installed once; SHA-256 over length-delimited `(org,project,kind,owner_key)` interpreted as big-endian first uint64 modulo 64. Owner keys: metrics canonical name+sorted labels; logs canonical stream labels; spans trace ID; errors occurrence ID; job attempts run ID; replay/profile their root IDs; condition source-condition ID; capability/loss source+producer+kind. Source descriptors expose public routing identity/version, never read permissions. SDK/adapters normalize then partition records by slot before assigning independent batch IDs, with one in-flight batch per producer+slot lane. Server verifies every owner key; mixed-slot batch is terminal 422 with safe route hints and zero admission. Replica placement may change for a slot through Raft membership, but the slot number/hash never silently changes.

HTTP `POST /ingest/v1/batches`: authorization header for private sources; browser key may use `X-Soundpost-Source`, with exact configured CORS origins and exposed retry/receipt headers. No wildcard origin reflection with cookies. Browser requests do not carry user session cookies. 1-MiB compressed/4-MiB expanded limit, 256-KiB record and 512 records. Response is `{version:1,batch_id,hash,cursor:{group,index},retain_until_ns,signal_deadlines,dedup_until_ns}`. Canonical JSON forbids duplicate keys and nonfinite numbers; typed float fields use hex bits. Atomic admission/retry behavior follows design section 6; C12 specifies cross-group fences and reservations. No upstream envelope/route is implicit.

## C05. Storage, scans and control state

`internal/storage/read.go`:

```go
type ReadFence struct { Min []model.Cursor; AllowPartial bool }
type ScanRequest struct {
    Projects []model.ID
    Signal ingest.Kind
    Start, End model.UnixNano
    Selectors []Matcher
    Projection []Field
    Fence ReadFence
}
type RowIterator interface {
    Next(context.Context) (Page, error)
    Watermarks() []model.Cursor
    Close() error
}
func (e *Engine) Scan(ctx context.Context, scope auth.Scope, req ScanRequest) (RowIterator,error)
```

`Matcher`, `Field` and `Page` are declared in `internal/storage/scan_types.go`: typed label/field matches (name, operator, literal), a closed field ID enum and immutable column pages with row IDs/time/value/loss metadata. `Next` returns `io.EOF` only on complete exhaustion; missing shard, corrupt page or denied scope is not EOF. Pages borrow iterator-owned memory until next `Next`/`Close`; consumers copy only retained values. `Scan` enforces scope before index lookup. Time range uses explicit signal semantics; a raw scan is `[start,end)` with evaluator helpers requesting the extra sample bounds they need.

`internal/storage/live.go` owns `(*Engine).Subscribe(ctx,scope,SubscribeRequest)(ChangeIterator,error)`; `SubscribeRequest{Projects,Signal,Selectors,After []Cursor}` uses the same scope and typed matchers. `ChangeIterator.Next(ctx)(ChangePage,error)`, `Watermarks()` and `Close()` provide bounded committed-apply events, explicit cursor gaps and revocation. Scans can catch up a retained range but live delivery is a real apply subscription, not polling. ChangePage includes origin cursors/rows/gap metadata and the same borrowed-page lifetime. C06 SSE filters this feed through the owned evaluator and revalidates every chunk.

`internal/storage/manifest.go`: `Publish(ctx, groupID model.ID, expected model.Revision, replacement Manifest) (model.Revision,error)` is a node-local layout operation guarded by the engine mutex and a revision compare-and-swap; it takes no leader term, no quorum read and no group lock, so every voter maintains its own physical layout whether it leads every group, some groups or none. This is safe because the manifest describes only that node's local files (segments, page locations, snapshot coverage): it is never replicated through Raft and never adopted from a peer on snapshot install (a snapshot transfers the manifest and segments as a verified set, but the receiver rebuilds its own layout from it), it carries no acknowledgement, receipt or externally visible effect, and every reader of it serializes on the same mutex. Acknowledgement, receipt lookup and any externally visible effect remain fenced by a live quorum observation (`Group.ReadIndex`, `Fence`/`ValidateFence`). The manifest `Term` field is a format constant pinned to 1 and MUST NOT be read as a freshness proof. `Manifest` contains checksummed segment identity/org/project/type/time/format/retention, index references, applied cursor, tombstone generation and snapshot coverage. A publish cannot evict the only committed copy or truncate WAL before verified snapshot coverage. (Amended after task 01.07: the earlier text required leader-term fencing, which made a node that did not lead all 65 groups unable to flush or compact; the independent 01.07 review could not refute the removal.)

`internal/control/store.go`: `Transact(ctx context.Context, scope auth.Scope, cmd Command) (Result,error)` commits deterministic control transitions with expected entity version and command ID. Closed commands include `CreateOrg`, `Grant`, `PolicyChange`, `BeginFence`, `CompleteFence`, `ReserveAdmission`, `FinalizeAdmission`, `ApplyIssueEvidence`, `ApplyCondition`, `ApplyRuleEvaluation`, `IncidentAction`, `ClaimDelivery`, `CompleteDelivery`, `DeleteScope`, `Audit`, `RegisterRelease`, `UpdateJob` and `RecordEvidenceGap`. `Result` includes new revision, affected IDs and control cursor. Time/random/network effects are supplied outside apply. Data→control effects carry `(group,index,record ID)` and apply once; C12 defines coordination without claiming atomic transactions across groups.

Control-generated effects are an outbox in the same control transaction. A worker checkpoints its source data cursor only in the transaction that applies all lifecycle effects from that cursor. Crash replay is idempotent; a human action does not pretend to atomically change telemetry storage. Deletion generations are checked at query admission and response release, before any cache hit and throughout streams.

Lifecycle evidence (error/condition/job transition projection with origin cursor) has its own declared 90-day retention journal in the owning data group, not a volatile queue. Before unprocessed evidence expires, commit `RecordEvidenceGap` with interval/cursor/count to control and set affected health incomplete/unknown; if that gap cannot commit, retain the journal and reject further admissions on reserved-capacity exhaustion. Privacy deletion overrides journal retention and suppresses derived effects through the C12 fence. Ordinary expiry never silently advances a processing checkpoint.

## C06. Own query/discovery/live interfaces

`internal/query/engine.go`: `New(scanner Scanner, policy Revalidator, profiles Registry, limits Limits) (*Engine,error)` and `(*Engine).Execute(ctx context.Context, scope auth.Scope, req Request) (Result,error)`. `Scanner.Scan` exactly matches C05; `Revalidator.Revalidate` matches C02. `Registry` owns immutable profile/feature manifests and `Limits` owns allowed request budgets. `Request` in `internal/query/types.go` has `Language`, pinned `Profile`, `Expression`, instant or start/end/step `Evaluation`, `Projects`, registered valid `FeatureSet`, `Budget`, `MinCursors` and `AllowPartial`. Rules always set AllowPartial=false. Every language evaluation runs independently inside one project; multi-project requests return separate project-keyed results, never one vector with merged hidden project identities.

`Result{Projects []ProjectResult}` contains one authorized project result per requested project. `ProjectResult{ProjectID,Value,Diagnostics,Watermarks,Completeness,Stats}` uses Value union `Scalar|String|InstantVector|RangeMatrix|LogStreams` with exact types/values/times/labels. Diagnostics contain ordered severity/code/source_range/safe_message; completeness is complete/partial/stale and stats are actual. Staleness is semantic absence, not a user-visible NaN sample. Language-defined order and histogram semantics are preserved. Errors retain language category/source range, not upstream HTTP text/status. Nanosecond log times stay strings. No cross-project arithmetic/joins are implicit; explicit dashboard panels may compare separately authorized project results.

HTTP `POST /api/v1/query` with the typed JSON request/result above; own `POST /api/v1/discover` with `{projects,signal,kind:metric_names|label_names|label_values|templates|fields,field?,matchers,time,limit,cursor?}` returns scoped names plus truthful pagination/freshness. `POST /api/v1/exemplars` and `/api/v1/query/format` are owned interfaces using the same scope/profile. Telemetry text is not put in GET URLs. Pagination cursors are authenticated, org/project/policy-bound and expire after 15 minutes; deleting/revoking invalidates them.

`GET /api/v1/live` establishes authenticated SSE with a short-lived server-created stream ticket selected by `POST /api/v1/live-tickets`. Parameters, selectors and scope reside in ticket state, not query-string secrets. Events contain sequence, current watermark, safe record or explicit gap/revoke/error; reconnect uses `Last-Event-ID` only while within the 60-second replay buffer. It is a real stream, not polling, and never claims guaranteed delivery. Scope revalidation occurs on every chunk. SSE does not claim Loki WebSocket compatibility.

Conformance fixtures use a semantic adapter for upstream oracle results; oracle HTTP is not the product interface. No production route forwards expressions to upstream engines. Native trace/issue/job/replay/profile search is typed Soundpost discovery/read, not an invented claim those entities are expressible in PromQL/LogQL.

## C07. Releases, errors, jobs and rules

`internal/artifacts/service.go`: `Put(ctx, scope, Manifest, io.Reader) (Artifact,error)` and `Get(ctx, scope, ArtifactID) (io.ReadCloser,error)`, with stream caps and hash validation. `internal/symbolicate/service.go`: `Resolve(ctx, scope, BuildID, []Frame) ([]SymbolicatedFrame,error)`. `Manifest` includes org/project/build/debug IDs, generated/map SHA-256, path identity, source-content policy and size. Max bundle 32 MiB expanded, at most 1024 files, map nesting depth 8, per-frame CPU deadline 100 ms; symbolicator subprocess total 5 seconds/256 MiB. Source content is an explicit artifact grant and retention policy. No runtime URL fetch.

Server ownership is explicit: plan09 owns artifacts/sourcemap/symbolicate/replays; UI owns HTTP adapters; SDK owns build uploader/recorder/viewer. `BuildID`/`ArtifactID` alias model.ID. Private artifact bytes use `(*storage.Engine).WriteBlob(ctx,scope,manifest model.BlobManifest,input io.Reader)(model.BlobReceipt,error)` in `internal/storage/blob.go`, implemented by plan09 over the same replicated storage groups. Model.BlobManifest binds org/project/root/build/hash/size/policy/retention; BlobReceipt includes durable fragment cursors/hash. Internal ArtifactFragment entries are not public telemetry Kind or arbitrary attachment capture: split at256 KiB, fixed root-owner slot, durable quota token/fences and full snapshot coverage. Put returns only after all bytes and control reference publication commit; orphans remain unreadable and GC requires proof. No separate external blob database.

`internal/replays/service.go` owns injected `Read(ctx,scope,replayID,ReplayWindow)(ReplayStream,error)` and `Validate(grant,model.ReplayChunk)error`. ReplayStream carries checkpoint/delta/gap/revoke/error and closes scoped resources; C11 UI obtains only this authorized stream. Read/dependency retention cannot fabricate continuity; backend validation does not replace pre-buffer SDK privacy.

`internal/issues/types.go` owns `Evidence`, `Issue`, `IssueAction`; pure `internal/issues/group.go` owns `Fingerprint(version uint16, org,project model.ID, occurrence model.ErrorOccurrence) ([32]byte,error)`. Injected `internal/issues/service.go` owns `ApplyEvidence(ctx,scope,Evidence)(Issue,error)` and `Act(ctx,scope,IssueAction)(Issue,error)`. Evidence includes origin cursor/record ID, grouping/fingerprint, release ancestry, event time, ordinal and count/denominator provenance. Issue stores workflow/group identity, release windows and resolution frontier. IssueAction is resolve/ignore/unignore/reopen/grouping_migration with command ID/expected version/reason and issues.write. Unknown release ancestry is not lexically sorted.

`internal/jobs/reducer.go`: `Reduce(current JobState, event JobAttemptEvent) (JobState,error)` is deterministic. Attempt terminal conflicts with the same version are rejected, newer explicit corrections are separate audited events. Schedule occurrence key includes scheduled UTC instant plus configured timezone/fold; default spring-forward nonexistent local occurrence is skipped with schedule evidence, fall-back runs once for each distinct UTC instant. Default overlap is `allow`, missed-run grace 5 minutes, and explicit cancellation is `cancelled`, not success. A late old run cannot overwrite health from a newer schedule occurrence. SDK loss/outage makes schedule health unknown until an external schedule observer has evidence. Run, attempt and current job health have separate fields.

`internal/jobs/types.go` owns `JobState{Definition,CurrentHealth,LatestScheduleKey,Runs,Attempts,IncompleteIntervals}` and separate immutable run/attempt terminal state; reducer never conflates current health with historical failure.

`internal/rules/types.go` owns `Rule`, `Evaluation` and fenced output DTOs; `FenceToken` is `internal/replica.FenceToken{Group,Term,Revision}`. `internal/rules/evaluator.go` owns an injected `Evaluator` and `(*Evaluator).Evaluate(ctx, scope, Rule, at model.UnixNano, lease FenceToken) (Evaluation,error)`. Rule declares profile/FeatureSet/expression/interval/for/recovery hold/missing-data policy/project/severity/version. Evaluation contains time/input cursors/state/diagnostics and deterministic recording/condition intents. `ApplyRuleEvaluation` atomically stores `(ruleID,version,at)`, fence, state and internal output intents in control; workers emit recording batches via normal Admit with stable IDs, then finalize each intent. This internal output outbox is distinct from external notification Delivery. No cross-group atomic output promise; retries reconcile durable intent+receipt. Unknown/error cannot reset ACK or fire recovery.

Rule also declares Kind (recording/alert), RecordName and output Labels explicitly. Injected `RuleStateReader.ReadEvaluation(ctx,scope,ruleID,version,at)(Evaluation,bool,error)` returns a committed observation verbatim; nondeterministic LogQL `now` is actual injected wall time, not silently replaced by evaluation time. Only the first fenced committed payload at `(ruleID,version,at)` can produce effects. `internal/rules/output.go` owns `(*OutputWorker).Flush(ctx,scope,lease,limit)(OutputReport,error)` for finalized/retried/suppressed internal intents and cursors; plan06 consumes, never reimplements it.

## C08. Incident/outbox behavior

`internal/incidents/types.go` owns `State`, `Action`, `Effect`; `internal/incidents/reducer.go` owns pure `Apply(state State, cmd Action, at UnixNano) (State, []Effect,error)`. Action has command ID/expected version/actor/reason/target and kind (`open`,`ack`,`resolve`,`assign`,`impact`,`snooze`,`unsnooze`,`maintenance`,`maintenance_end`,`link`). State separates human status, linked condition freshness, impact/ACK revisions, snooze and maintenance scope/reason/expiry, timeline. Effects are safe outbox/audit intents, not network calls. ACK cannot change underlying conditions/issues/impact. Stale versions conflict; same command retry returns its original result.

`internal/notify/types.go` owns Delivery/Outcome; `internal/notify/outbox.go` owns scoped `Claim(ctx,scope,now,lease FenceToken,limit int)([]Delivery,error)` and `Complete(ctx,scope,deliveryID ID,attempt uint32,outcome Outcome)error`. Delivery includes stable idempotency ID, org/policy/entity/impact revision/kind/recipient, safe template fields, next attempt and fence expiry. Outcome kind is accepted (provider ID), retry (safe code/retry-after), terminal (safe reason) or unknown (possible provider acceptance before timeout/crash). Unknown remains visible and retries keep the same delivery ID; immutable attempt audit preserves uncertainty. Exactly-once external delivery is not claimed. Urgent/reminder/worse-impact/recovery and queue/digest share one canonical policy reducer.

Default policy exact values: 5-minute error window, urgent on critical approved operation code OR (>=20 observed operations AND >=5 failures AND >=5% rate) OR qualifying regression with >=5 occurrences. Counts refer to deduplicated occurrence IDs; denominator from a named complete operation metric. Unknown denominator never produces a rate. Initial reminder 15 minutes then every 60 minutes; ACK suppresses reminder kind only. Daily 09:00 recipient timezone digest (UTC fallback); expired snooze reevaluates current state once. Missing channels are visible failed-delivery state, not silent success.

Notification retry proposal is at most12 attempts or24 hours, whichever first; capped jittered delays1 second→15 minutes, honoring provider Retry-After within that budget. Unknown provider outcomes remain visible and keep delivery ID; provider acceptance is not human receipt. `notify.Sender.Send(ctx,auth.Scope,Delivery)(Outcome,error)` is the consumer-owned seam implemented by providers and wired in internal/app. Signed webhooks use HMAC-SHA256 over `timestamp.deliveryID.exactBody`, a5-minute receiver freshness window and fresh persisted timestamp/signature each attempt; body/delivery ID are stable. Egress resolves and validates DNS plus actual dial addresses, prohibits unapproved private/link-local/loopback destinations, disables redirects by default and repeats checks on every connection.

## C09. SDK public surfaces

Python package `soundpost`, TypeScript workspace packages `@soundpost/browser`, `@soundpost/node`, `@soundpost/bun`, `@soundpost/build`. Names are proposed logical names; registry reservation is not claimed. Consumers may use local wheels/tarballs if public names are unavailable; published naming is checked before release, not silently changed in docs.

Python `init(config: Config) -> Client`, `Client.capture_exception(error: BaseException, *, code: str | None = None) -> EventID`, `Client.span(operation: str, *, dependency: str | None = None) -> SpanContextManager`, `Client.job_attempt(job: str, run_id: str, ordinal: int) -> AttemptContextManager`, `Client.flush(timeout: float = 2.0) -> FlushReport`, `Client.close() -> None`. Context manager is sync/async capable and isolates request context. Config registers templates, source endpoint/credential, safe identities, origin propagation, policy, queue caps and enabled integrations. `capture_exception` never inspects exception values/locals unless an explicitly permitted message template supplies safe fields; arbitrary objects are not accepted for serialization.

TypeScript `init(config: Config): Client`; `captureException(error: unknown, options?: {code?: string}): EventId`; `withSpan<T>(operation: string, fn: () => Promise<T>, options?: SpanOptions): Promise<T>`; `withJobAttempt<T>(job: string, runId: string, ordinal: number, fn: () => Promise<T>): Promise<T>`; `flush(timeoutMs?: number): Promise<FlushReport>`; `close(): Promise<void>`. Runtime profile `startProfile(options: ProfileOptions): Promise<ProfileHandle>` requires explicit optional configuration; `ProfileHandle.stop(): Promise<ProfileReport>` returns capability/loss/cursor, never a heap profile or listener. Handlers preserve preexisting hooks and fatal-exit behavior. Queue cap 2 MiB/1024 records, exporter age 5 minutes, 2-second flush, retry 250 ms→30 s as in design.

SDK policy trust uses an Ed25519 envelope `{version:1,algorithm:"Ed25519",key_id,payload,signature}`. Payload/signature are unpadded base64url. The signature covers exact canonical UTF-8 payload bytes; verify against the deployment's installation-bound `key_id`/32-byte public-key map before interpreting the policy. Canonical policy JSON sorts object keys, rejects duplicate keys and nonfinite/floating policy numbers, and uses canonical decimal strings for counters/times. Policy binds organization/project/source, revision and expiry. Unknown keys, invalid signatures, mismatched identity or expired policy fail closed; deployment configuration can only narrow approved capture. This elaborates the approved signed-policy requirement; it does not permit remotely enabling bodies or unmasked replay.

Native JSON field names are snake_case. The SDK's internal safe-record buffer is not a second ingestion protocol. Batch construction supplies the complete C03/C04 fields, canonical owner routing and exact decimal/hex values before transport.

## C12. Cross-group barriers, reservations and recoverable cuts

Policy restriction/source revocation/deletion is a durable saga, not a ReadIndex-only illusion: (1) control commits closing epoch and operation, denies new grants/affected reads and pauses derived effects; (2) each affected slot drains already ordered work and commits its new epoch/tombstone barrier, rejecting old-epoch proposals ordered after it; (3) control records every barrier cursor, suppresses deleted-origin derived/outbox effects and marks complete. Operations return202 while fencing. Writes ordered before their slot's barrier may finish/ACK under the old policy before operation completion; after completion none may. Unavailable groups prevent completion, never silently skip a fence. Membership changes inherit current barriers before readiness. The same saga fences control→data recording-rule intents and source policy changes.

Hard org/project quotas use durable control reservations bound to batch hash, slot, policy epoch, canonical admitted bytes and new canonical series IDs. Reserving occurs before data proposal; the data-group apply validates the token and commits consumption with the batch. Ambiguous proposal leaves the reservation charged. Release only after owner-group linearizable evidence of no committed batch and a committed cancellation fence preventing future use; TTL/router death alone never refunds it. Finalization is idempotent by reservation/batch ID. Cardinality is canonical per project, not multiplied by producer; metadata reservation cost is included in performance gates.

Until explicitly configured, each organization/project quota object derives a conservative cap from the first admitted source policy and tightens to the minimum subsequently admitted policy cap. A source-policy increase alone does not raise these shared caps: an authorized, audited quota change must configure them explicitly. The source tier follows its current fenced source policy, including authorized increases, while preserving existing charges. Lowering any cap denies further excess admission; it never refunds or erases acknowledged data. Deployments needing independently sized sources should configure organization/project caps before intake.

Data snapshots carry every retained authoritative byte or verified pinned complete transfer set; manifests alone are insufficient. WAL truncation waits receipt/apply/tombstone/full-data coverage. At installation backup control cut C/processed cursors H, pin the required post-H lifecycle journal before workers/retention can remove it; seal data snapshots D>=H with replay-or-explicit-gap interval certificates through D. Pin data, evidence and reservation/consumption/release proofs until all bundles seal; privacy deletion of a pinned target aborts/restarts an in-progress backup or updates its deny certificate. Preserve pending intents. A missing group or post-H replay range fails backup. Copying may continue while intake proceeds, but no needed replay history may be reclaimed.

Before restored intake opens, reconcile global quotas against the selected data cut: every D carries consumed reservation IDs and exact per-retention live logical-byte/series charge state plus release certificates. Reconstruct exactly one control charge per consumed reservation, including those created after C; reconcile reservations in C with D and committed cancellation fences without unsafe refund/double charge. Recompute canonical live series from the restored project index as a cross-check. Persist a verified `QuotaReconciliation` certificate before readiness; missing charge/proof blocks admissions. Disk-physical capacity is separate from logical admitted-byte quotas.

Disaster restore needs deletion state newer than a possibly old backup. Enabling off-host backup therefore requires a separately durable restore-authority journal (versioned object store with verified strong read-after-write, conditional HEAD update and retained immutable generations, or equivalent verified independent storage). Every deletion operation, including historical predicates, writes and verifies its signed/encrypted generation plus monotonic authority HEAD before completion. Authority failure leaves deletion fencing, not success. Ingest ACK does not depend on this store. Restore must obtain/validate the current authority HEAD/ledger before any data read; unavailable/unverifiable authority fails closed. Backup modes without this authority may make local recovery copies but cannot claim deletion-safe disaster restore. No operator override quietly resurrects acknowledged-deleted data.

Disaster restore uses a fresh bootstrap-only authentication generation and keys even when installation identity is retained. Every pre-restore bearer credential, session, elevation, API/source key and sender credential is inactive. Restored local users/passwords/MFA/recovery codes, grants and OIDC mappings are inactive until audited reconciliation with current identity authority or explicit per-account/grant reauthorization by a newly bootstrapped recovery admin. Old decryption keys decrypt data only and never reenable authentication. Normal user data reads, active source intake and external delivery remain disabled until that reconciliation/activation completes. Old token logout/revocation/account demotion after backup cannot be undone by restore.
