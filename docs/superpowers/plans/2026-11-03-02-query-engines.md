# Soundpost Own Query Engines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** APPROVED for implementation by Aryn Yklas on 2026-11-03 with m1 implementers and m2 reviewers. Planned compiler/oracle/test/conformance commands are acceptance instructions, not exercised results.

**Goal:** Implement independently authored, complete PromQL 3.1.0/3.13.5 and LogQL 3.5.2 language engines, owned query/discovery/live interfaces, isolated input translators and fenced rule evaluation without an upstream production engine.

**Architecture:** Owned parsers produce typed trees and bounded column/vector plans over the C05 authorized scan seam. Profile registries preserve version/configuration-specific semantics, annotations and ordering; isolated reference processes are development oracles only. C06 exposes Soundpost envelopes and C07 derives durable recording/condition effects through the control outbox, never through a hidden upstream evaluator.

**Tech Stack:** Proposed Go 1.27.3, Go standard-library RE2 and `text/template` primitives, owned query/evaluation packages, C01 typed values, C05 storage/control primitives; isolated pinned Prometheus/Loki executables only in the conformance harness. Libraries and build digests require the approved dependency-lock task from plan 01, not an installation during planning.

**Spec:** `docs/superpowers/specs/2026-11-03-soundpost-requirements.md` (R01–R04, R10–R18, R22–R24), `docs/superpowers/specs/2026-11-03-soundpost-design.md` §§4–8, 12–13, `docs/superpowers/specs/2026-11-03-soundpost-contracts.md` C01–C07/C11. Active evidence: `docs/research/2026-11-03-primary-source-research.md` §4; archived recommendations are not requirements.

## Global Constraints

- All first-party product code and authored cases are Apache-2.0. Retain third-party license/NOTICE and source/hash provenance; no copied or translated AGPL Loki grammar, evaluator, iterator or test tables.
- Full language compatibility, not a dashboard-driven subset. No upstream-disabled gate is enabled implicitly; no unimplemented enabled gate is reclassified as unsupported. Intermediate tasks do not constitute complete-profile acceptance.
- Exact profiles: `promql-prometheus-3.1.0` / `7086161a93b262aa0949dbf2aba15a5a7b13e0a3`; `promql-prometheus-3.13.5` / `f497435984d1ca1d84cda5ed309387ac2eb1f8f6`; `logql-loki-3.5.2` / `257d2f62bf8a81b44dea6fe88968d1d28c8e01e7`.
- Own ingestion, indexing, storage, query execution and rule evaluation. No production Prometheus/Loki evaluator dependency, RPC forwarding, subprocess fallback or telemetry-engine replacement.
- Own C06 routes and envelopes. No Prometheus/Loki HTTP/admin/target parity, Grafana/LogCLI compatibility, Loki WebSocket compatibility, Sentry-compatible ingestion or OTLP receiver promise.
- Every access requires C02 `auth.Scope` or a validated source grant. Project filters are not authorization. Revalidate before response, every stream chunk and at most 5 seconds apart during compute; authorization/deletion failures cannot become empty-success results.
- C01 IDs/nanoseconds/uint64 use canonical strings; floats use exact `FloatBits`. Distinguish ordinary NaN from stale `0x7ff0000000000002`, preserve signed zero/infinity and native integer histogram count/delta precision. No histogram-to-float fallback.
- Cache, cursor, ticket and stream visibility identity includes principal or a complete effective-grant fingerprint, including named restricted-source reader entitlements, in addition to org/project/permission/policy/deletion/profile/query/time parameters. Equal broad `raw.read` does not imply equal source visibility.
- C05 raw scans are `[start,end)`; language selectors/evaluation grids retain their pinned semantics. Borrowed pages expire at `Next`/`Close`; copy only retained columns/values.
- Default query budget is 30 seconds, 256 MiB working memory and 5 million returned samples/logs, capped further by endpoint limits. Explicit bounded higher grants are permitted; exceeding a limit returns a typed error, never silently truncated complete results. Cancellation releases iterators, temporary files, RPC and memory. Spills are org-scoped encrypted temporary files with deletion fencing.
- Rule queries always set `AllowPartial=false`. Unknown/error/stale producer/missing shard never implies recovery or clears a human ACK. Default missing-data policy is unknown; default recovery hold is zero.
- Telemetry/query text is not placed in GET URLs, diagnostic logs or default audit payloads. Raw-source reads additionally require `raw.read`; templates cannot fetch environment, filesystem or network contents.
- Pagination cursors are authenticated, org/project/policy/deletion-bound and expire after 15 minutes. Live replay is 60 seconds; live is a genuine stream with explicit gaps, not polling or a guaranteed-delivery claim.
- No private customer paths, infrastructure inventory, hostnames or ADR identifiers. Only generic fixtures; production adoption has separate authorization.
- All listed implementation/test/fixture paths are proposed **Create** operations: no product sources exist at planning time. Existing common specifications are parent-owned and are not edited by this plan. Each task updates its own tracked ledger/acceptance evidence instead of creating speculative product capability claims.

## Review Focus

1. **Mixed sample kinds and nonfinite bits:** histogram/float windows, resets, ordinary NaN and stale removal must produce profile-correct values/removals/ordered annotations, not plausible float answers — Tasks 3–4, final cross-product in Task 12.
2. **Boundary time and duplicate inputs:** left-open metric windows, inclusive evaluation grids, log `[start,end)`, nanosecond ties and legitimate duplicate records must survive normalization/compaction/restart — Tasks 3, 7–8, 12.
3. **Mutation/template/regex discrepancies:** newline labels, `__line__`, extraction collisions, stage order and template runtime failures must match the pinned language without exposing arbitrary capabilities — Tasks 5–7.
4. **Scope changes during work:** cross-project aggregation, cache hits, cursor reuse and live reconnect after revocation/deletion must fail closed, including borrowed-page and cancellation cleanup — Tasks 9–10, 12.
5. **Incomplete rule input and replay:** late watermarks, missed evaluations, stale leases, crash replay and backfill must not fabricate recovery, duplicate recordings or retroactive live notifications — Task 11 and its real-control smoke.

## Dependencies and exact ownership

Plan 01 supplies C01 model/ingest types, C02 scope/revalidation, C03 policy/admission, C05 `storage.Engine.Scan`, immutable pages, durability/control transactions, authorization HTTP middleware and the approved module/dependency lock. This plan does not recreate storage, Raft, ingest ACK or source-policy machinery. End-to-end tasks wait for those dependencies; pure parser/evaluator tasks use explicitly named in-memory implementations of the same scan contract, never substitute mocks in final acceptance.

C05 seam consumed unchanged:

```go
type Scanner interface {
    Scan(context.Context, auth.Scope, storage.ScanRequest) (storage.RowIterator, error)
}
```

The request includes authorized projects, signal, raw start/end, typed selectors/projection and `ReadFence{Min,AllowPartial}`. Iterator errors remain errors; only actual exhaustion is `io.EOF`. Unsafe pushdown is forbidden: the evaluator owns residual language matching, missing/empty-label treatment and extra selector bounds.

**Shared dependency contracts:** C06 uses `(*query.Engine).Execute` with explicit injected scanner, policy revalidator, profile registry and limits. C07 uses `(*rules.Evaluator).Evaluate`; rule types reside in `internal/rules/types.go`. C05 includes `ApplyRuleEvaluation`: atomically commit `(rule ID,version,evaluation time)`, fenced state/input cursors/diagnostics and versioned recording/condition effects to an internal output outbox. Recording delivery then uses ordinary C03 durable admission with stable identities; this is not a cross-Raft-group atomic transaction. Internal rule outputs are distinct from external-notification `Delivery` types. No global engine or direct hidden state writes are permitted.

Language execution is independent per project. A C06 Request may list authorized projects, but Result is project-partitioned; evaluate and compare each project separately, never inject hidden project labels or combine colliding series across projects. Native metric identity is `(project,name,sorted labels)`, not producer. Exact timestamp/type/value duplicates collapse; differing values conflict atomically at the owner shard. Native logs retain an immutable safe line rendered from the admitted registered-template revision and typed fields; historical lines are never rerendered after template changes, and stream labels remain separate from structured metadata. SDKs/adapters partition batches into one of the fixed 64 virtual slots using the canonical record owner key; this plan consumes that C03/C05 routing contract rather than implementing a second shard router.
