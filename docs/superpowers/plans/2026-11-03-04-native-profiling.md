# Owned Native Linux CPU and Off-CPU Profiling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status: DRAFT — NOT AUTHORIZED FOR EXECUTION.** Full-design approval by Aryn Yklas and an execution-method choice are required first. Every implementation, fixture and test path below is a planned **Create**. No compiler, dependency, kernel capability, performance test or runtime profiler was exercised while preparing this plan.

**Goal:** Deliver a first-party Linux perf-event CPU/off-CPU engine with fixed authorized acquisition, evidence-correct scheduler correlation, bounded resources, privacy-preserving export and measured per-kernel/architecture/runtime coverage.

**Architecture:** A short-lived, locally authorized privileged acquisition helper opens only a fixed CPU/scheduler event configuration and sanitizes kernel ABI records before a bounded local socket. An unprivileged session correlates sanitized numeric events and exports typed Soundpost profile chunks. Per-session correlators, generation identities and loss watermarks prevent unrelated targets or uncertain intervals from becoming invented blocking evidence.

**Tech Stack:** Proposed Go 1.27.3; Linux `perf_event_open`, mmap rings and tracefs ABI metadata; Linux 6.1/6.6 LTS amd64/arm64; ordinary ELF/build-ID metadata and controlled debug artifacts. No eBPF, ptrace memory access, user-stack dumps or third-party profiling engine.

**Spec:** [Requirements R08–R09, R15–R16, R22–R24](../specs/2026-11-03-soundpost-requirements.md), [design sections 3, 5, 10, 13](../specs/2026-11-03-soundpost-design.md), [contracts C01–C05, C09–C11](../specs/2026-11-03-soundpost-contracts.md), [active evidence sections 2–3](../../research/2026-11-03-primary-source-research.md). Source-backed feasibility is not completed runtime qualification.

## Global Constraints

- All first-party code/tests are Apache-2.0; kernel is an OS prerequisite, not relicensed into the product. Independently author Linux ABI bindings/tests from documented layouts; do not copy GPL scheduler implementations or restricted test corpora. Record provenance and review redistributed dependencies/UAPI notices.
- Qualified target proposal: Linux kernels **6.1 and 6.6 LTS, amd64 and arm64**, perf events/tracefs enabled, authorized cgroup/process targets and sufficient `CAP_PERFMON`/host permissions. Every exact kernel/config/architecture/build row is unqualified until exercised.
- No automatic sysctl relaxation, broad root daemon, kernel module, eBPF program, remote inspection command, arbitrary tracepoint selector, `/proc/<pid>/mem`, ptrace reads, DWARF stack-byte capture, locals/heap/object/argument/return-value capture or register dumps.
- C10 `Target{CgroupID,PIDNamespace,TGID,ProcessStart,AllowedBuildIDs}` and `Config{CPUHz:99,MaxFrames:128,RingBytes,ReorderWindow:100ms,MaxMemory:64MiB,PolicyRevision}` remain the acquisition contract. CPU frequency is requested, not an achieved-accuracy promise.
- C10 public seam: `Probe(ctx context.Context, targets []Target) (Capabilities,error)`, `Open(ctx context.Context, targets []Target, cfg Config) (*Session,error)`, `(*Session).Next(ctx context.Context) (SanitizedEvent,error)`, `(*Session).Close() error`. Unsupported platforms return typed capabilities/errors, not empty fake events.
- Per-session state: `NewCorrelator(cfg Config) *Correlator`, `(*Correlator).Consume(event SanitizedEvent) ([]Interval,error)`, `(*Correlator).Advance(watermark model.MonoNano) ([]Interval,error)`. No package-global correlation state; the parent-owned C10 contract incorporates this clarification.
- CPU event sample fields are `PERF_SAMPLE_IP|TID|TIME|CALLCHAIN`, with fixed sample-ID/clock bookkeeping only as needed for ABI correlation. No `PERF_SAMPLE_STACK_USER`, register dump fields or arbitrary raw CPU payload. Scheduler tracepoint input necessarily uses fixed kernel ABI fields; only allowlisted numeric values are read and exported.
- The kernel mmap ring may transiently contain fixed command names/path fields from its ABI. Skip them without copying to application buffers, diagnostics or socket. The ring itself is not a sanitized artifact and is never persisted/transmitted as `perf.data`. Sanitized export contains only authorized numeric scheduler fields, addresses/module identities and loss/clock/generation metadata.
- Frame-pointer callchains are the baseline. Missing frame pointers, permission denial, JIT/perf-map limitations and absent switch-out callchains produce explicit coverage/truncation reasons. No raw-memory unwind fallback. Thread-off-CPU does not claim complete suspended-async-task ancestry.
- Native profile gate: <=3% CPU overhead per profiled target workload, bounded **64-MiB acquisition/export memory**, observed sample loss and correct nonzero blocked intervals under the stated 99-Hz plus scheduler fixture. Do not weaken a budget or substitute runtime timers for native sampling.
- Backend ingest/authorization/storage comes from C02–C05. Profile read is C10 `Read(ctx, scope, profileID ID, req Window) (ProfileView,error)` with C11 scoped investigation UI; all links/exports revalidate grants and deletion generations.
- C03 routing uses 64 fixed owner-key slots, not producer shards. Normalize and partition profile/capability/loss records by their canonical owner slot before assigning batch IDs; profile root ID is its owner key. One in-flight batch per producer+slot; mixed-slot batch rejects 422 before any commit. Receipts retain original per-signal deadlines plus minimum retain-until across retry, expiry and deletion without resurrecting data.
- Inject all stateful dependencies through consumer-owned narrow interfaces and scope-bound instances; `internal/model` is a leaf. No profile/collector imports of storage implementations or mutable global services; concrete C03/C05 adapters live in `internal/app`.

## Review Focus

1. Untrusted process exits, execs or reuses a PID while events are in flight: Tasks 2, 5 and 6 must reset generations and never join new processes to old stacks/intervals.
2. Foreign wakeup, migration, preemption and cross-CPU reorder produce a convincing but wrong blocked/runqueue split: Tasks 4–5 require evidence-complete intervals, explicit unknowns and bounded watermark behavior.
3. Kernel command names/paths or secret stack contents escape a supposedly numeric collector: Tasks 3–4 and 8 audit pre-socket buffers and actual exfiltration with canaries, not just a clean final JSON object.
4. CPU hotplug, high core counts, full rings and many targets defeat fixed FD/memory budgets: Tasks 2–4 and 9 must refuse explicitly, account every active resource and close cleanly on cancellation.
5. Optimized/JIT/runtime builds, denied permissions or missing callchains become fabricated support: Tasks 6–7 and 9 retain real samples with honest unresolved/truncated reasons, method/units and runtime-specific qualification.

## Dependencies, limitations and release handoff

Tasks 1–4 establish actual authorized acquisition; Task 5 independently tests the evidence algorithm but does not claim native runtime coverage on synthetic events. Task 6 supplies safe generation/symbol identity, Task 7 integrates real durable admission/scoped reads, Task 8 proves privacy end-to-end, and Task 9 is the mandatory real-kernel/runtime/overhead gate. No native profiler release is complete with runtime-only samples, empty profiles, stubbed system calls or a clean final JSON that ignored earlier capture leaks.

Frame pointers and permission/configuration are prerequisites, not magically repaired by this engine. A CPU sample may have a useful native chain and an unresolved JIT frame. Scheduler records may have valid task/time evidence but no user switch-out stack. Async I/O can block a task without representing every suspended language coroutine. Missing foreign wakeups or losses can invalidate split attribution even while CPU samples remain valid. Each distinction survives ingest, storage, C10 ProfileView and exports; UI plan consumes rather than erases them.

C10's stateful correlation clarification is parent-owned: `Correlator` receivers and `NewCorrelator` replace ambiguous global free-function state. This plan does not change C09 or promote runtime supplements to native OS CPU units. The native collector remains required alongside replay and the full SDK scope.

Before execution, obtain full-design approval and choose Subagent-driven (recommended for privilege/privacy plus independent kernel review) or Native. After approved implementation, release evidence must name exact kernel/config/architecture/runtime/build, privilege policy, actual sample/loss/intervals, privacy checks, overhead and sanitized durable receipts. Desk research and this draft are not that evidence.
