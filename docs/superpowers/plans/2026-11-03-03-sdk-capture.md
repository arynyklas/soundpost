# Custom SDK, Replay and Runtime Capture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** APPROVED for implementation by Aryn Yklas on 2026-11-03 with m1 implementers and m2 reviewers. Every source/test/fixture path is Create until implemented; planned commands are acceptance instructions, not qualification results.

**Goal:** Deliver owned Python and browser/Node/Bun capture SDKs with real critical paths, durable-receipt-aware delivery, exact release artifacts, attempts, privacy-first replay and honestly typed runtime supplements.

**Architecture:** Construct allowlisted typed records before buffering, then share a bounded Soundpost v1 delivery model across independently implemented Python and TypeScript clients. Owned adapters preserve application behavior and isolate request context. A separate recorder produces only sanitized replay structures; a separate inert renderer consumes that stream. Runtime supplements declare actual methods and coverage rather than replacing the native engine.

**Tech Stack:** CPython 3.12/3.13/3.14 standard GIL; strict TypeScript; Node 22/24; Bun 1.3.14; browser DOM/MutationObserver; ordinary runtime HTTP, context and inspector APIs. No Sentry or OpenTelemetry SDK wrappers.

**Spec:** [Requirements](../specs/2026-11-03-soundpost-requirements.md), [design sections 5–6, 9–10, 13, 15](../specs/2026-11-03-soundpost-design.md), [contracts C01–C04, C07, C09–C11](../specs/2026-11-03-soundpost-contracts.md). [Active primary evidence](../../research/2026-11-03-primary-source-research.md) establishes feasibility/limits, not qualification.

## Global Constraints

- All first-party server, SDK, replay and profiling code is Apache-2.0. Dependency versions, license closure and hashes are locked at approved execution, not inferred from product names.
- Own contracts throughout: `/ingest/v1/batches`, C03/C04 payloads, C09 public signatures; no upstream envelope/API parity or OTLP/Sentry receiver. Full PromQL/LogQL language scope remains unchanged and belongs to the query plan.
- Core targets CPython 3.12/3.13/3.14 standard GIL on Linux/macOS/Windows; Node 22/24 and Bun 1.3.14 separately. Free-threaded/JIT/subinterpreters/PyPy start unqualified. Native Linux profiling is a separate deliverable.
- Python public API: `init(config: Config) -> Client`; `Client.capture_exception(error: BaseException, *, code: str | None = None) -> EventID`; `Client.span(operation: str, *, dependency: str | None = None) -> SpanContextManager`; `Client.job_attempt(job: str, run_id: str, ordinal: int) -> AttemptContextManager`; `Client.flush(timeout: float = 2.0) -> FlushReport`; `Client.close() -> None`. Both context managers support sync/async use.
- TypeScript public API: `init(config: Config): Client`; `captureException(error: unknown, options?: {code?: string}): EventId`; `withSpan<T>(operation: string, fn: () => Promise<T>, options?: SpanOptions): Promise<T>`; `withJobAttempt<T>(job: string, runId: string, ordinal: number, fn: () => Promise<T>): Promise<T>`; `flush(timeoutMs?: number): Promise<FlushReport>`; `close(): Promise<void>`. Browser additionally `setReplayConsent(enabled: boolean): void`.
- Queue cap 2 MiB/1024 records, exporter age 5 minutes, 2-second flush, one in-flight batch per producer+route-slot lane, retry 250 ms→30 s with jitter. C03 limits: 512 records/batch, 256 KiB/record, 1 MiB compressed/4 MiB expanded. Decimal-string nanoseconds and exact hex float bits, never JS-number time conversion.
- Error occurrences do not depend on trace sampling; default enabled tracing is 100% until explicit budgets require reported probability/loss. No bodies, credentials, prompts/responses, full SQL/parameters, locals/globals, arbitrary objects, console arguments, source context, raw URL/query/fragment or exception messages by default.
- Replay requires project policy AND deployment opt-in AND explicit consent/session sampling. Maximum chunk 128 KiB; checkpoint every 30 seconds or after a gap. All text/input values use one constant mask token before buffering.
- Proposals below are qualification targets, not observed support. Do not advertise integration/support until the exact runtime/browser/framework combination passes the real matrix. No silent skipped rows.
- Backend ingest, artifacts, symbolicator and job reducer are consumed through C03/C07; SDK code must not implement alternate backend contracts. Every task includes package documentation and changelog entries at its owned planned paths; no shared design edits during execution without contract review.
- Routing is C03 v1: 64 fixed virtual slots, SHA-256 over length-delimited `(org,project,kind,owner_key)`, big-endian first uint64 modulo 64. Normalize then partition by owner slot before assigning batch IDs; public source descriptor routing metadata grants no authorization. C01 integer histograms retain tagged decimal uint64 counts/int64 deltas, including values above 2^53.
- Each initialized client owns immutable policy revision and mutable queue/context/integration leases explicitly; no mutable process-global client/service singleton. Runtime-global hook/inspector ownership uses bounded explicit leases, not hidden shared exporters. Registered template ID+revision produces one immutable safe rendered log line; later template edits never rerender history.

## Review Focus

1. Hostile exception/DOM values execute getters or leak through temporary queues: pre-buffer canaries and getter/repr traps in Tasks 1, 2 and 7 must remain absent from queue bytes and export/diagnostics.
2. A server commits but loses its response: Task 3 retries identical identity/content, releases records only after matching durable receipt, and reports ambiguous shutdown honestly.
3. Concurrent requests, cancellation and nested hooks contaminate another context or alter exit behavior: Tasks 2, 4 and 5 prove isolation, coexistence and unchanged outputs/exit codes.
4. Replay opt-out, reorder and missing checkpoints create plausible false history: Tasks 7 and 8 destroy pending capture and resume only at a validated checkpoint with a visible gap.
5. Bun/worker/browser restrictions or profiler ownership conflicts become invented CPU evidence: Tasks 6 and 9 keep capability reasons, scope, units and loss distinct and run Bun independently of Node.
