# Investigation UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** APPROVED for implementation by Aryn Yklas on 2026-11-03 with m1 implementers and m2 reviewers. Planned interfaces and commands are requirements, not implemented or exercised capabilities.

**Goal:** Deliver a native, authorized investigation experience that takes a real failure through queue, incident, release, query, critical path, job, masked replay and correctly qualified profile evidence.

**Architecture:** A strict-TypeScript React application uses Soundpost's C06/C11 read and action surfaces; server handlers construct C02 scopes and delegate to owned engines. Views preserve typed values, independently authorized links, freshness and uncertainty rather than manufacturing unified success. Artifact/replay/profile access is separately granted, and authentication is real local/OIDC authentication, not a frontend role switch.

**Tech Stack:** Go 1.27.3 server; TypeScript strict mode, React and Vite with embedded production assets; Playwright real-browser acceptance. Exact frontend/test dependency versions and licenses are locked by the approved build work before implementation, not invented here.

**Spec:** `docs/superpowers/specs/2026-11-03-soundpost-requirements.md`, `docs/superpowers/specs/2026-11-03-soundpost-design.md` §§4, 8–11, 14–15; `docs/superpowers/specs/2026-11-03-soundpost-contracts.md` C01/C02/C04/C06/C07/C10/C11. Active evidence: `docs/research/2026-11-03-primary-source-research.md`; archived product comparisons are not contracts.

## Global Constraints

- All first-party product code, SDKs, SSO, isolation, replay and profiling are Apache-2.0; no paid-only gate. Use only reviewed licensed dependencies and preserve notices.
- Own APIs, schemas and native UI throughout: no Sentry/Keep UI or API parity, no Prometheus/Loki HTTP parity, no OTLP requirement and no upstream engine fallback. Preserve full PromQL/LogQL language semantics under all three pinned C06 profiles.
- Pinned language profiles are `promql-prometheus-3.1.0`, `promql-prometheus-3.13.5` and `logql-loki-3.5.2`; use their complete registered feature combinations, not a dashboard-selected subset. Default request budget is 30 seconds, 256 MiB working memory and 5 million samples/logs, bounded further by endpoint limits and scoped grants.
- Every path below is a planned **Create**: no source files exist at planning time. Test/smoke commands are future execution instructions, not checks performed during this design assignment. Commit instructions are also future, gated actions.
- C01 IDs and nanoseconds remain canonical strings at the wire/browser boundary; do not round nanoseconds/uint64 through JavaScript `number`. IEEE values/native histograms remain typed, not flattened to generic JSON floats.
- Every request uses a C02 scope; links, caches, artifacts, exports, discovery and SSE are independently authorized. Wrong-scope/missing targets are indistinguishable. Revocation/deletion revalidates before response and every chunk; long computations have at most a 5-second lease.
- C02 `VisibilityFingerprint` includes principal and every effective named-source grant; server/cache projections must distinguish telemetry-only and restricted-source readers even inside the same project. Restore uses a fresh auth generation: old users/grants/OIDC credentials stay inactive until audited reauthorization, with visible bootstrap-only/reauthorization state.
- C12 closing operations deny affected reads immediately, return HTTP 202 while all-shard barriers/derived-effect suppression are fencing, and report success only after completion. Show operation progress, held/failed state and physical/backup deadlines; immediate read denial is not immediate physical erasure.
- C06 evaluates each project independently and returns `Result{Projects []ProjectResult}`. Compare explicit project panels only; no injected project label, colliding-series merge or implicit cross-project language join.
- Additional grants are `artifacts.read`, `replay.read`, `profiles.read` and the restricted-raw grant alongside `telemetry.read`; frontend hiding is never enforcement. Instance elevation requires reauthentication, reason, committed audit and 15-minute expiry.
- Show empty, loading, unauthorized, unsupported, stale, incomplete, rate-limited and error separately in every view. Missing/unknown telemetry is not zero, successful delivery, recovery or supported sampling.
- UI values are bounded plain text, never telemetry HTML. Full query text stays in POST bodies and browser memory; explicit project-owned saved-view authorization is required to persist it. Never place query text, credentials or captured values in URLs, analytics, logs or notification links.
- Reuse SDK-plan `packages/replay-viewer/src/render.ts` renderer and native-plan C10 `internal/profiles/service.go` read service. This plan does not implement either collector/recorder or duplicate those services.
- Generic adoption fixture identities only. No private customer paths, infrastructure inventory, hostnames or ADR identifiers. No product/customer deployment is authorized.

## Review Focus

1. Revocation or elevation expiry while a detail page, source view or SSE connection is open must clear subsequently forbidden content and stop subsequent chunks — Tasks 1–2 and 5 browser tests.
2. Out-of-order browser responses after project/time navigation must never paint the old scope into the new page — Task 2 `scope-response-race.spec.ts`.
3. Missing shards, absent denominators and unsupported profiles must remain unknown/incomplete rather than graph zeros or healthy rates — Tasks 3, 5 and 8 tests.
4. Concurrent human actions must surface conflicts while preserving typed drafts, not silently overwrite somebody else's owner/ACK/snooze — Task 3 `incident-actions.spec.ts`.
5. Concurrent trace branches, unlike clock domains and replay gaps must not become invented causal duration or seamless playback — Tasks 6 and 8 algorithm/browser tests.

## Ownership, files and interfaces

The identity/control/query/storage/SDK/native plans supply the real C01–C10 services. This plan owns HTTP UI projections, browser application behavior and browser acceptance; the incident plan owns C07 issue/job state and C08 incident/notification reducers. Server projection types live in C11 `internal/httpapi/workflow_types.go`; browser mirrors live in `web/src/api/types.ts`. These parent-accepted type paths are Soundpost types, not imported competitor schemas.

`InvestigationRequest` is a closed `kind` union for queue, incident, issue, release, service, trace, job, replay and profile. It contains authorized `projects`, stable typed target ID or typed filter, explicit window, bounded limit/cursor and minimum cursors; it never contains caller-supplied scope. `InvestigationView` is the matching closed view union with entity revision, authorized links, completeness, watermarks, capability/loss/freshness and authenticated pagination. C11 `ActionRequest{CommandID,ExpectedVersion,ProjectID,TargetID,EntityKind,Kind,Payload}` has closed payloads for C08 incidents and C07 issue `resolve|ignore|unignore|reopen|grouping_migration`; `ActionResponse` returns revision/operation status and safe view. No generic arbitrary JSON selector is allowed. `LifecycleOperation{ID,Phase,Generation,PendingGroups,AppliedBarriers,SafeFault,PhysicalDeadline,BackupDeadline}` has phase `fencing|complete|held|failed`; GET `/api/v1/operations/{id}` performs scoped polling, delegating deletion to C11 `PollDelete`. These parent-accepted wire definitions must stay synchronized with final C11/C12.

All browser components below return `React.JSX.Element`. `ViewContext` in `web/src/app/context.ts` contains selected organization, project IDs, environment, `[start,end)` nanosecond strings, timezone and request generation; it is navigation state, not an authorization token. `LoadState<T>` in `web/src/api/types.ts` is a closed union `loading|ready|empty|unauthorized|unsupported|stale|incomplete|rate_limited|error`, with ready/partial data only in variants where permitted.
