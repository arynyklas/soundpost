# Incidents and Notifications Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** APPROVED for product implementation by Aryn Yklas on 2026-11-03 with m1 implementers and m2 reviewers. Customer cutover and disruptive customer drills remain separately authorized. Planned commands are not executed results.

**Goal:** Build Soundpost-owned error/job/condition lifecycles and one canonical incident/notification workflow that preserves evidence, respects human actions and reports delivery uncertainty honestly.

**Architecture:** Deterministic reducers consume committed, scoped evidence into distinct alert-condition, recurring-error-issue and human-incident entities. C05 control transactions apply evidence/checkpoints/audits/outbox atomically within the control group; fenced workers perform queries and network delivery outside deterministic apply. A single policy reducer owns urgent notifications, reminders, worse-impact updates, queue and digests; the independent external deadman is explicitly outside the product failure domain.

**Tech Stack:** Go 1.27.3; owned models/reducers/storage/rules; C05 Raft-backed control store; standard-library testing and real SMTP/Telegram/HTTPS integration fixtures. Generic infrastructure libraries are reviewed and pinned in the approved build work; no competitor workflow/schema is copied.

**Spec:** `docs/superpowers/specs/2026-11-03-soundpost-requirements.md` R12–R18/R21–R24; `docs/superpowers/specs/2026-11-03-soundpost-design.md` §§8–9, 11, 15; `docs/superpowers/specs/2026-11-03-soundpost-contracts.md` C01–C08/C11. Active evidence: `docs/research/2026-11-03-primary-source-research.md`.

## Global Constraints

- All first-party product, SSO/isolation/SDK/replay/profiling code is Apache-2.0 with reviewed dependency notices. Own native contracts throughout; no Sentry/Keep API/schema/UI parity or OTLP requirement.
- This is a draft plan. Every implementation/test/document path below is a planned **Create**; no source files exist. Tests, smoke commands and commits are future gated steps, not performed checks or capability claims.
- Reuse C01 canonical IDs/times/errors and C02 opaque `Scope`; workers use real project-scoped service principals. Authorization is not a label filter. Every view/action/destination/secret/outbox/export is scoped and revalidated.
- C05 `Transact(ctx context.Context, scope auth.Scope, cmd Command) (Result,error)` uses command ID, expected entity revision and deterministic inputs. No wall-clock read, random generation or network send inside replicated apply. Data→control provenance `(group,index,record ID)` applies once; checkpoint only with all lifecycle effects, with no cross-group atomicity fiction.
- C05 lifecycle evidence has a separate authoritative 90-day data-group journal. Before unprocessed evidence expires, commit `RecordEvidenceGap` with interval/cursor/count and mark affected health incomplete/unknown; if gap cannot commit, retain the journal and reject further admissions on reserved-capacity exhaustion. Never silently advance processing checkpoints.
- C12 policy/source/deletion closing pauses derived effects and denies affected reads immediately; all-group barriers, origin-effect suppression and required deletion-authority checkpoint must complete before success. HTTP 202 fencing is not completion. Privacy deletion overrides the evidence journal and pending rule/notification effects.
- Dependencies remain acyclic: feature packages define narrow consumer-owned store/query/clock/provider interfaces; `internal/app` composition adapters bind them. Control state machine imports leaf DTOs only, never issues/jobs/rules/incidents/notify implementation packages; notification worker does not import its provider implementation subpackage.
- Alert condition, error issue, run/attempt/current-job health and incident human response are distinct. ACK pauses reminder-kind delivery only. It does not repair sources, resolve issues or suppress a new material-impact notification.
- Proposed exact default urgency: 5-minute error window; critical approved operation code OR (`>=20` observed operations AND `>=5` deduplicated failures AND `>=5%` rate) OR qualifying regression with `>=5` occurrences. Named complete denominator provenance is mandatory for a rate. Missing/stale/partial data is unknown, never zero/recovered.
- One opening notification, first reminder after 15 minutes then every 60 minutes while unacknowledged; worse impact has its own impact revision. Daily 09:00 recipient-timezone digest with UTC fallback; queue is immediate. Snooze/maintenance require reason/actor/scope/expiry, maximum 7 days by default, and never suspend ingestion/evaluation/failure display.
- Default rule recovery hold is zero unless configured; missed evaluations are recorded; no retroactive live notifications from backfill without explicit replay mode. Full PromQL/LogQL semantics and pinned profiles remain required, not a rule-expression subset.
- Delivery attempts may repeat under ambiguous failures; neither exactly-once external delivery nor guaranteed eventual provider acceptance is promised. Stable IDs, immutable attempt audit, fencing and provider dedup where available bound duplicates. Missing channels and retry exhaustion are visible failed/uncertain delivery, never success.
- Destinations are org-owned; secrets use C02 AES-256-GCM envelope encryption with separately restricted keys/KMS and redacted reads. Approved templates only, configured public origin and per-org egress allowlists. Never paste raw logs/error messages/source/replay/profile into external channels.
- Generic adoption fixtures only; no private hostnames, paths, customer inventory, ADR IDs or implicit production authority. Independent external deadman stays separately operated outside the product's failure domain; legacy history remains read-only through its real retention/export obligations.

## Review Focus

1. Late, duplicated or out-of-order evidence after resolution/release changes must append history without manufacturing regression or replacing newer state — Tasks 1–4 tests.
2. Concurrent humans, ACK and newly worse impact must preserve optimistic concurrency while pausing reminders only — Tasks 5–6 tests.
3. Missing denominator, stale producer, incomplete query or unknown release ancestry must never invent a percentage or recovery — Tasks 2, 4 and 6 tests.
4. Leader loss or provider acceptance before sender death must preserve stable delivery identity, expose uncertainty and reject stale completion — Task 7 fault tests and Task 8 real-provider test.
5. Cutover/rollback and whole-product outage must never create two normal-notification owners or take down the independent deadman — Task 9 acceptance.

## File and contract ownership

This plan owns C07 `internal/issues/{types,group,service}.go`, `internal/jobs/{types,reducer,service}.go`, `internal/rules/{types,evaluator}.go`; C08 `internal/incidents/{types,reducer,service}.go` and `internal/notify/{types,policy,outbox}.go`. It consumes query/storage/control/auth/ingest from their plans. It does not create duplicate engine, SDK, UI, source adapter or cluster deployment implementations.

Shared additions accepted for the draft: `internal/issues/types.go` declares `Evidence`/`Issue`; `internal/jobs/types.go` declares `JobState`; `internal/rules/types.go` declares `Rule`/`Evaluation`; `internal/incidents/types.go` declares `State`/`Action`/`Effect`; `internal/notify/types.go` declares `Delivery`/`Outcome`. The parent-owned contracts must carry these same definitions before coding. `Action` includes `maintenance`/`maintenance_end`, distinct from `snooze`/`unsnooze`. `Outcome.Kind` is `accepted|retry|terminal|unknown`; unknown represents possible acceptance and retry keeps the original delivery ID. Stateful services have injected stores/clocks/providers, not package globals; C07/C08 shorthand functions below describe those method operations without changing contract semantics.

`Evidence` retains occurrence ID and origin cursor, grouping version/hash, event and arrival time, release/build ID and ancestry knowledge, producer epoch/ordinal, source freshness and a named denominator with complete window/cursors. `Issue` retains immutable occurrences/late history, workflow `open|resolved|ignored`, resolution frontier, observed releases, fixed-descendant frontier, grouping migration links and count/rate/regression provenance. `JobState` keeps definitions/runs/attempts/current-health separately. `State` keeps incident human status, linked-source condition/freshness, impact revision, ACK revision/time, owner, scoped snooze, separate scoped maintenance, timeline and version. All wire uint64/nanoseconds use C01 strings.
