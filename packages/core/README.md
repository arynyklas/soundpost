# Policy-first capture

Copyright 2026 Aryn Yklas. SPDX-License-Identifier: Apache-2.0.

This package implements policy-first capture, native spans and bounded native HTTPS delivery. Runtime integrations have explicit owned leases; jobs, replay recording and profiling remain separate APIs/tasks. No record is acknowledged merely by entering the queue. `bufferedRecords()` returns immutable serialized safe snapshots, never raw exceptions. `flush(timeoutMs = 2000)` releases only verified durable receipts; `close()` finalizes unfinished spans, flushes, releases owned hooks/transport/spool leases, and records nondisk pending destruction as loss.

## Installation trust and policy protocol

The installation supplies trusted Ed25519 public keys by key ID. Policy envelope fields are `version:1`, `algorithm:"Ed25519"`, `key_id`, `payload`, `signature`; the last two are canonical unpadded base64url. Verify exact canonical UTF-8 payload bytes before interpreting fields. Required payload keys are version/org/project/source/revision/expires_ns/errors/logs/replay/bodies. Approved additive `traces`/`jobs`/`loss` keys must be strict booleans; absence denies each permission independently of errors. Deployment traces/jobs/loss switches default true and only narrow actual signed permission. Unknown keys, duplicates, floats/nonfinite values, identity mismatch and untrusted signatures fail closed. Permission bits do not install integrations or implement job APIs. Installation trust roots are pinned deployment input, never downloaded from the envelope itself.

The deployment allowlist intersects policy booleans. Raw bodies are never an available capture input, even when both policy permissions allow them. Replay permission is only a decision value, not a recorder. Templates and approved resource identities are deployment registrations; signed policy alone cannot register arbitrary content. Resource service/environment/build identities are canonical nonzero opaque IDs, not human aliases. Approved field values are exact finite primitive enums, not arbitrary strings. Unknown fields are discarded without reading their values. Template revisions must increase; buffered lines and template revisions never change.

Every template registration explicitly supplies severity from `trace | debug | info | warn | error | fatal`; it is immutable per revision and preserved in the record. Text bounds count strict UTF-8 bytes in both SDKs: template line 4096, approved string field 256. Unpaired Unicode surrogates reject rather than silently replacing text. Config org/project/source/build identities are canonical nonzero 32-character lowercase hex IDs, never deployment display aliases. Verified policy org/project/source IDs must match those exact IDs. Policy/template revisions are canonical uint64 decimal strings (0 through 18446744073709551615); expiry and observed_at_ns are canonical signed int64 UnixNano strings (-9223372036854775808 through 9223372036854775807), including negative timestamps and rejecting -0/leading zeros. Past expiry is a policy-expired admission outcome, not overflow. Invalid/throwing injected clocks drop capture with only an invalid_clock counter; capture does not echo values or propagate clock exceptions. Runtime package type exports use the owned `@soundpost/core/types` boundary.

## Record mirror

The SDK-local safe JSON record has `kind` (`error`, `log` or `span`), `id` (32 lowercase hex), `observed_at_ns` (exact decimal string), `policy_revision` (decimal string), and `payload`. Error payload: `occurrence_id`, `exception_class`, `code`, `build_id`, `handled`, `fatal`, `mechanism`, root `frames`, `exception_graph` (`nodes`, `edges`, `reasons`) and optional validated `trace_id`/`span_id`. Nodes carry bounded class symbols, their safe frames and context suppression; edges preserve cause/group references including cycles and shared children. Limits are 16 nodes and 128 frames per occurrence, with explicit overflow reasons. No message, arguments, values, locals or source content are admitted. Log payload: `template_id`, `template_revision`, `fields`, `line`, `severity`, `stream_labels`, `structured_metadata`, `source_class`. Span payloads use native C04 fields described below. Queue caps remain 1024 records/2 MiB UTF-8, 256 KiB per record, five-minute pending age.

Runtime entrypoints supply a safe native-error brand. Node/Bun use `node:util.types.isNativeError`; the browser uses intrinsic `Error.isError` only where present, otherwise reports `native_brand_unavailable` and `UnknownError`. Unknown throws/proxies are not inspected. Cause/group accessors are never invoked. JS frames currently carry `safe_original_stack_unavailable`: even a V8 own stack descriptor can trigger lazy custom formatting. Caller-stack APIs are not substituted for original error frames. Foreign/custom prototypes are reported conservatively; browser group containers without a safe proxy boundary report `safe_group_boundary_unavailable`.

## Explicit handling episodes and hook ownership

`client.beginHandlingEpisode()` returns a caller-owned token. `episode.captureException(error, options?)` captures one logical occurrence and thereafter returns its stable occurrence ID; `episode.close()` is idempotent and prevents further use. The token retains only its client and safe ID, never a raw error/stack/object ID. A token is **one logical handling episode**, not a general error identity cache: use a new token for every new occurrence, even if the application reuses the same exception instance.

`installHooks(client)` is exported by runtime packages, not installed implicitly by init. Each client permits at most eight open leases. Node/browser `lease.useEpisode(episode, error, mechanism)` arms one exact weakly referenced object identity for `uncaught_exception` or `unhandled_rejection` on that lease's native source. Primitive throws cannot be weakly identified and reject association with `weak_error_identity_required`; they still capture independently. Unrelated sources or error objects capture their own occurrences and do not consume another arm. Up to eight pending arms are permitted; `lease.clearEpisode(episode)` explicitly cancels an arm, and close clears all arms. No raw errors/object IDs are retained or user errors mutated. First-observation handled/fatal/mechanism metadata stays immutable on ID reuse. Python's explicit nonweak-source context contract is documented in sdk/python/README.md; Bun's unavailable monitor rejects arming.

### Shared C04 exception vocabulary

Both SDKs use one closed mechanism enum: `manual | uncaught_exception | unhandled_rejection | thread_exception | asyncio_exception`; graph edge kinds are `cause | context | group`. JavaScript does not invent Python context edges. Python `None` and JavaScript absent/null/undefined causes mean no cause edge/node. A present non-nullish JS non-Error cause remains a constant `UnknownError` node with `unknown_throw`, never its primitive/object value. These are the local C04 error-field spellings for the later batch/ingest mapping, not runtime-specific aliases.

`fatal` describes observation of the process-level default-fatal path, not a prediction or confirmed process exit: true for Python sys.excepthook and Node uncaughtExceptionMonitor, even if an application's prior handler/capture callback chooses to continue; false for browser reporting, Python threading and asyncio task/loop failures. A thread/task may end, but the SDK does not infer process fate from that event.

Leases preserve prior hook order/default handling, remove only owned callbacks, and are idempotent. Application-owned fatal/rejection behavior remains authoritative. Actual runtime qualification and full original/source-mapped JS exception frames remain separate unmet gates, not implied by local class capture.

## Native delivery and resources

`Config.resource` is required: `{service_id, environment_id, build_id, instance_pseudonym, labels?}`. Obtain IDs and the approved instance string from the source's real registered resources; `resource.build_id` must equal `Config.build`. Labels use the native sorted unique `{name,value}[]` representation, not an object map. Optional `Config.descriptor` consumes the server's `{version:1,org,project,source,routing_version:1,slots:64,policy_revision}`; all identities/revision must match Config and its verified signed policy. Omitting it constructs exactly that public fixed64 descriptor from the already bound Config, never an authorization scope or alias translator.

Normalization precedes routing, partitioning and batch-ID allocation. SHA-256 length prefixes are uint32 big-endian **UTF-8 byte lengths**; the big-endian first uint64 modulo64 selects the slot. All ten native owner kinds are implemented; metric identity excludes source/producer. Native JSON uses Go-compatible UTF-8 key ordering and U+2028/U+2029 escaping. Integer histogram strings never pass through Number. Golden owner/native-input bytes live in `fixtures/sdk/delivery/{routing-vectors,native-vectors}.json`.

The queue caps at2MiB/1024 records, rejects records over256KiB, expires exporter work at5minutes, and splits each ordered lane at512 records/1MiB uncompressed HTTP body (also below the4MiB expanded ceiling). Lower-priority unfrozen timing/replay/profile work yields to errors/control; already frozen unacknowledged batches are never evicted for new work. Loss reasons/counts contain no dropped content. Batch producer/slot/ID/canonical bytes/hash/first capture/policy revision stay fixed.

The default transport requires an HTTPS `/ingest/v1/batches` URL without embedded credentials/query/fragment. Private clients send only `Authorization: Bearer`; the browser entrypoint sends only `X-Soundpost-Source` with `credentials:omit`, no referrer and redirects forbidden. TLS verification remains enabled. Applications configure approved exact browser origins on the source; the SDK does not create wildcard CORS or ingestion cookies.

`FlushReport.receipts` preserves batch/hash/cursor, per-kind deadlines, their minimum retention deadline and dedup deadline. ACK means durable append only, not indexing or rule processing. Matching identity/hash, nonzero canonical cursor index, exact signal-kind set and minimum deadline are mandatory. Invalid/mismatched receipts remain pending;401/403 stops that client's exporter; new-admission409/422 is terminal visible loss.429/503 use bounded Retry-After and250ms–30s jittered retries. A concurrent flush has its own deadline without creating a second writer.

An ambiguous/unread response first uses current source authentication on `/ingest/v1/receipts` with original source/producer/slot/batch/hash. Only a matching `historical:true` receipt releases it. Policy narrowing/data expiry never rerenders, changes hash or reappends a known commit. Only authenticated not-found permits reconsidering admission; expired/changed policy drops uncommitted work with explicit loss instead of inventing an ACK. Revoked sources/retired scope stay denied. Unread keepalive/beacon delivery is unacknowledged.

## Opt-in backend spool

No default client writes a disk queue, and the browser rejects any configured spool. Node/Bun expose `await openEncryptedSpool(path, protected32ByteKey, descriptor, policyRevision, maxBytes?)`, then pass its result as `Config.spool`. AES-256-GCM authenticates scope/routing/policy headers; only typed identities/revision are plaintext, never payloads or source credentials. Authenticated original-policy state can recover under a newer policy for historical lookup, never automatic old-policy admission. Writes use capped encrypted atomic replacement and file fsync; supported POSIX filesystems also sync the directory. This is process-restart recovery, **not** Windows namespace/power-loss or kill-proof delivery qualification.

Each disk backend owns an exclusive live-process contender lease. Concurrent leases, corruption/authentication failure, capacity/disk failures are explicit; none creates an empty successful ACK. Python uses OS advisory locks; Node/Bun use immutable per-process contender files and conservative PID liveness (PID reuse can deny availability rather than steal ownership). Async backend writes are awaited by flush/close; a sudden kill before those writes finish can still lose work. Close preserves encrypted pending batches and releases handles/leases. Installation key protection, filesystem capacity and exact runtime qualification remain deployment responsibilities.

## Exact additive C04 metadata

The internal codec recognizes optional metric `start_timestamp_ns` as canonical signed-int64 decimal metadata: absent/null omits, `"0"` stays present, negative and above2^53 values remain exact, and future values are not rejected or substituted with observed time. Full-profile query semantics decide its use.

Approved native-profile supplements remain closed typed structures: clock/task/generation, real sample method/unit/period and99Hz request, exactly three unique capability references including the primary, bounded256-entry native loss/throttle evidence, policy revision/sequence and completion. Native profile policy revision must match the enclosing record; legacy runtime profiles can genuinely omit native metadata. Throttle transitions carry count0 plus explicit event/stream IDs, never durations or fabricated loss counts. Native off-CPU chunks cannot contain CPU samples. Corrections are consumed before persistence; true correction flags reject.

Native resolved frames carry only64-lowerhex module identities, safe bounded symbol characters and optional nonzero128-bit artifact references; an empty module requires a closed unresolved reason and zero offset/empty symbol/artifact. Missing capability records remain incomplete/unknown at authorized readers, not SDK-inferred denial or support. These DTOs do not claim a public SDK profiler implementation or qualify a runtime.

Queue accounting includes each native resource-bearing record plus bounded batch-header headroom. Frozen payload bytes are retained once; safe snapshots are reconstructed from that immutable body instead of keeping a second payload copy. Five-minute expiry removes an entire frozen batch at its earliest capture, including after encrypted restart. Filesystem failure diagnostics count failed persistence attempts, not dropped contents.

## Native spans and explicit runtime context

`await client.withSpan(operation, async () => result, {dependency?, kind?, parent?, signal?})` preserves the callback's value or rejection identity. Register finite `Config.operations` and `Config.dependencies` aliases first; URL, SQL, headers, parameters and arbitrary attributes are not span inputs. Signed `traces:true` and the deployment switch are independent of error admission. Enabled tracing defaults to probability `3ff0000000000000` (100%); an explicit `traceSampleProbability` is an exact finite float64 hex value in [0,1]. Errors remain independent of sampling. Sampling/active-span losses are counted without dropped content.

C04 spans carry independent record ID, trace ID, 64-bit span ID, nullable parent, kind/operation/dependency aliases, local start/end `{wall_ns,mono_ns,domain,uncertainty_ns}`, status, links, exact sample probability and decision. End is idempotent; close marks unfinished work `incomplete`. Local wall/monotonic decimal strings never round-trip through Number. Remote worker/HTTP clocks are causal links only, never a replacement local domain or a cross-domain duration subtraction.

Internal adapter seams are `startSpan` (context/run/end), `traceContext` and `withTraceContext`; they are not additional C09 authority APIs. The fourth constructor argument supplies a per-client metadata/clock scope independently from the third exporter-recursion scope. Node and Bun implement their own AsyncLocalStorage/`hrtime.bigint` adapters. Browser scope lasts only through synchronous callback invocation: capture context before await and explicitly supply it at the next boundary. `parent:null` deliberately starts a root. Without observed clock calibration all runtime stamps declare full-range uint64 uncertainty (`18446744073709551615`), not an invented synchronization/accuracy bound. Same-domain monotonic durations remain useful; cross-domain overlap is unknown. Browser performance timestamps are elapsed signals, not CPU profiling; exact browser/OS resolution remains a qualification gate.

Worker propagation is a closed versioned envelope of canonical trace/span IDs, sampling and clock-link IDs only. It contains no source/project/credential or arbitrary worker payload. A worker initializes its own client/config independently. Incoming W3C `traceparent` must have a valid closed Soundpost companion to establish this adapter's sampling/clock link; a foreign or malformed pair is an honest missing parent, not guessed causality. Outbound adapters inject propagation only to exact registered origins and strip baggage.

Native sampling-loss emission additionally requires independently signed `loss:true` and `deploymentLoss` not false. Explicit trace-budget drops map to C04 signal `span`, reason `policy`; the active-span bound maps to signal `span`, reason `queue_full`. Local diagnostics keep the more precise `trace_sampled_out`/`trace_active_limit` names. A local counter is not an exported or acknowledged LossReport: native reports use the queue owner's source/producer/epoch/cursor, normal bounded partition/freeze path and matching durable receipt. Loss permission is never borrowed from errors or traces.

The maximum uncertainty is a conservative bound over the full representable wall range, not an observed synchronization measurement. Consumers must use checked/clamped arithmetic and an unknown cross-domain overlap result, never add that uint64 to an int64 timestamp and overflow. Local monotonic precision is not UTC accuracy. A trusted explicitly calibrated internal clock source can supply a smaller canonical decimal bound; no fixed 1ms/100ms capability is inferred.

Queue-owned `recordSignalLoss(signal, reason, bigintCount, atNs)` returns aggregation acceptance only, never an ACK. Its 512-byte aggregation buckets count against the same 2MiB budget; reports take the normal frozen C03/historical-receipt path. Only verified durable receipts increment acknowledged counts. Internal `signalLossCounters()` exposes exact-string observed/acknowledged/pending/unexported counts; expiration, terminal rejection and nondisk close remain unexported rather than being silently reappended. Expected accepted sampling is not unexpected `FlushReport.lost`; capacity/recovery failures remain visible. A cold encrypted spool can decline reporting until its producer state is recovered (`native_loss_recovery_pending`), never fabricate an epoch. This generic LossReport mechanism is separate from native-profile `native_loss` metadata.

## Manual job-attempt observations

Register at most1024 immutable `Config.jobRegistry` entries mapping safe aliases (`[A-Za-z0-9_.-]`,1–128 characters) to canonical nonzero lowercase32-hex JobIDs. The client copies the registry; later configuration mutation does not relabel observations. `await client.withJobAttempt("approved.task", runId, ordinal, async () => result)` requires a canonical nonzero32-hex run ID and a positive `Number.isSafeInteger` ordinal (maximum9007199254740991). Native ordinal/sequence/time values remain exact decimal strings; aliases, callback arguments/results and raw exception values never enter an attempt record.

Each invocation emits one `started` and one `succeeded`, `failed` or `cancelled` observation through the existing policy-first bounded queue. Attempt ID is stable across its two events; retries keep the run ID and obtain distinct attempt IDs. The client owns one random producer epoch and a monotonic bigint event sequence. Cancellation is a real intrinsic `DOMException` `AbortError`, or a trusted runtime-branded native Error with its own data-only `name:"AbortError"` and `code:"ABORT_ERR"` (including Node timers/promises). A Bun-style cancellation with no own fields additionally requires a separately runtime-issued brand: actual already-aborted standard timer rejection is compared with an actual non-abort timer rejection and generic Error prototypes. Only a distinct direct prototype identity is retained, never an error/value/client. Calibration is lazy, handled immediately, bounded at50ms and awaited before classification; no guessed cancellation exists while it is unavailable. Candidates undergo trusted native/proxy rejection before one direct prototype comparison, never a chain walk. Inherited/accessor/opaque/proxy fields and messages are not read, and classification carries no telemetry authority. Failed callbacks independently capture a privacy-safe error even when tracing is sampled out. Original return/rejection identity and application finally behavior are preserved. Queue/policy/clock failures can leave incomplete history; no ACK, durable receipt or current-health result is fabricated.

Failed/cancelled terminal wall time is observed immediately when the callback rejects, before awaited runtime-brand calibration or sanitized error processing. Calibration latency is not substituted for the callback's completion timestamp.

Signed `jobs:true` intersects `deploymentJobs`; errors, spans and native loss retain their independent permissions. Only actual job scope adds optional `run_id` to sanitized errors. Node/Bun use independent per-client async-local job scopes. Browser/core fallback scope is synchronous only: unrelated work after await has no guessed ambient job. The job wrapper explicitly rebinds its own terminal/error scope after await, so overlapping jobs cannot acquire each other's terminal links. Job scope is separate from trace context and is not serialized into arbitrary worker messages.

The schedule key `manual.<runID>` means **unscheduled observation**, not a cron definition, a missed-run diagnosis or healthy observer evidence. SDKs do not schedule work or calculate current health. Definition/run/attempt/current-health reconciliation, external-observer freshness and DST semantics belong to the server job lifecycle. Optional trace/error links do not prove target availability or grant reads. Parent-run tests and real C03/C05 journey fixtures are listed in `.superpowers/sdd/approved-product/03.05-jobs-report.md`; authored fixtures do not qualify any runtime/browser row.
