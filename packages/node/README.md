Policy-first local capture plus explicit `installHooks(client)` / idempotent `HookLease.close()`. Native error branding uses Node's `util.types.isNativeError`; causes and safe aggregate containers are descriptor-read without invoking user getters. `uncaughtExceptionMonitor` observes uncaught exceptions/strict unhandled rejections without installing any `uncaughtException` or `unhandledRejection` listener, changing rejection mode, or consuming default fatal exit. Existing application monitors/handlers/capture callbacks and their order remain authoritative. Closing removes only this lease's listener, never restores removed application handlers. Client close owns its leases (maximum eight).

See ../core/README.md for the exact graph/episode protocol: `lease.useEpisode(episode, error, "uncaught_exception" | "unhandled_rejection")` uses weak object identity plus monitor origin; unrelated errors/sources do not consume the arm. `clearEpisode(episode)` cancels it. Fatal marks the process-level default-fatal path, not confirmed exit if an application handler continues. V8 original stack extraction remains unavailable (`safe_original_stack_unavailable`), not full ordinary/source-mapped support; caller stacks are never substituted. Replay and profiling remain separate tasks. Node22/24 qualification is parent-run independently from Bun.

The arm mechanism follows Node's **native monitor origin**, not JavaScript throw syntax. An ES-module command-line entrypoint's top-level throw is a module-evaluation rejection and must arm `unhandled_rejection`; a later callback's ordinary throw arms `uncaught_exception`. The SDK does not merge these sources or weaken identity matching. The fatal fixture tests both paths independently and asserts actual monitor origin plus original-object identity. Node's documented contract: https://nodejs.org/download/release/v22.23.4/docs/api/process.html#event-uncaughtexceptionmonitor .

Native `flush(timeoutMs=2000)` now uses real HTTPS private-source delivery with matching durable receipt validation and historical-lookup-first ambiguous recovery. Config requires the source's real typed `resource`; public descriptor identities must match its signed policy. No cookie/redirect/TLS-verification bypass is provided. AsyncLocalStorage isolates exporter suppression without suppressing concurrent application capture; close disables its owned context and releases hooks/transport.

Default operation writes no disk queue. `openEncryptedSpool(path, protected32ByteKey, descriptor, policyRevision, maxBytes?)` is an explicit backend-only capped/authenticated spool factory; pass its result as Config.spool. Close retains encrypted pending identity and releases the exclusive lease. Fatal hooks still only capture/delegate; they never consume an exception or wait for network.

## Explicit critical-path adapters

Enable signed tracing and register finite operation/dependency aliases. `installExpress(client).handler("request", handler)` wraps an Express5 route and observes its actual response lifetime; promise rejection and synchronous throw identities are preserved. `installHttp(client, {operation:"request"}).listener(listener)` supports native HTTP servers through finish/close/abort, without adding consuming `error` or rejection listeners. Its explicit `request(url, options?, callback?)` wrapper supports HTTP/HTTPS clients and preserves ClientRequest identity. Use either a route wrapper or a native server wrapper deliberately; installing both creates deliberate nested spans.

`installFetch(client, {operation:"http.call", origins:[{origin:"https://dependency.example",dependency:"dependency"}]})` returns `lease.fetch(input, init?)`; it never patches global fetch. Only exact registered origins receive W3C traceparent plus the closed Soundpost sampling/clock companion. Baggage and foreign propagation are stripped for ordinary data-only request options; opaque/accessor options are delegated untouched rather than read by instrumentation and have no attributed span. Response identity/body streaming remain unchanged; the fetch span measures through response headers, not unobserved dependency internals or full body consumption.

`installPg(client, {operation:"db.execute",dependency:"postgres"}).query(poolOrClient, sql, values?, callback?)` wraps real pg8 promise/callback calls without capturing SQL, parameters, errors' messages or connection options. Callback this/arguments and synchronous errors are preserved. Unsupported cursor/query-object lifetimes produce `incomplete`, not successful fabricated durations.

Each client owns its own AsyncLocalStorage trace scope, distinct from exporter suppression. `serializeWorkerContext(client.traceContext()!)` creates only a closed causal envelope. Pass it as explicit worker data, initialize that worker's own client from independently supplied configuration, then call `withWorkerContext(workerClient, envelope, callback)`. IDs never grant tenant authority; remote domains never replace the worker's local clock. Single-install leases reject duplicate installation; close removes only owned listeners and finishes pending spans as incomplete. No telemetry exporter SDK or process-global current client is used.

Parent-run qualification: `bun test packages/node/test/integrations.test.ts` with PostgreSQL16; compile `fixtures/sdk/node/critical-path.mjs` using pinned Bun `--target=node --external express --external pg`, then execute the compiled artifact separately in Node22.21.1 and24.11.0. Bun-run tests alone do not qualify Node. The fixture requires private independently scoped writer/worker configs, real HTTPS dependency, PostgreSQL DSN and an independently authorized C05 verifier/read credential. It never uses a source bearer for reads. See the03.05 report for exact environment/build commands and unverified matrix rows.

## Manual job attempts

`Config.jobRegistry` binds finite safe aliases to canonical nonzero JobIDs. `withJobAttempt(alias, runId, positiveSafeIntegerOrdinal, async () => result)` emits native manual attempt observations through the existing queue, preserving results/rejections and intrinsic AbortError cancellation. A separate per-client AsyncLocalStorage job scope isolates concurrent callbacks and adds actual run links to sanitized errors; tracing decisions do not suppress failed-job errors. `manual.<runID>` is unscheduled/unknown-observer evidence, never cron health. See core documentation for signed jobs/deployment narrowing, exact IDs/time/sequence and incomplete-delivery semantics.

## HTTP client lifecycle boundary

HTTP client spans finish on the actual `IncomingMessage` body `end`, not `ClientRequest.close`. Request close does not prove body completion on every runtime; incoming abort/close/error remain explicit terminal evidence. Owned `errorMonitor` callbacks never consume ordinary application errors. A prepended response observer preserves native auto-discard when the application has no response consumer, without collecting body bytes. Request errors do not require an invented close event.

The standalone `fixtures/sdk/node/http-lifecycle.mjs` must be compiled and executed separately in actual Node22 and24; `fixtures/sdk/bun/http-lifecycle.ts` is a distinct Bun process gate. Both exercise gated body completion, callback receiver, no-consumer discard, actual socket-reset ownership and AbortSignal cancellation. Parent retains exact runtime/OS/build evidence; authored fixtures alone do not qualify a row.

## Optional runtime profile (explicit, off by default)

`startProfile({durationMs, intervalUs?, isolate?, projectRoot?, maxSamples?, eventLoopDelay?, client?})` returns a `ProfileHandle`; `handle.stop()` returns a `ProfileReport`. Nothing profiles unless you call it. It owns ONE in-process callback `node:inspector` session (no `inspector.open()`, no debugging listener, no `Runtime`/`Debugger`/`HeapProfiler` command: only `Profiler.enable|setSamplingInterval|start|stop|disable`), is bounded (<=60 s, <=8192 samples, <=128-deep stacks, every inspector command has its own 2 s timeout and `stop`/disable/disconnect/lease release always run in `finally`) and never throws into the application: refusal and failure are `handle.capability` / `report.capability` with a C04 status (`supported|denied|unsupported|error`) and a reason (`profiler_owned`, `isolate_scope_mismatch`, `invalid_options`, `client_unavailable`, `inspector_unavailable`, `inspector_timeout`, `inspector_error`, `profiler_state_lost`), always with zero samples.

The method is `runtime_engine_samples`: V8 engine samples plus engine time deltas (`units:"samples"`, `time_delta_unit:"engine_microseconds"`). It is NOT OS CPU time, assigns no CPU unit, observes only JavaScript frames of the calling isolate (`coverage`: frames/threads `partial`, workers/tasks `none`; no native frames, no suspended-Promise ancestry, no off-CPU time) and says so in the report. Frames are code identities only: a project-relative artifact path (only under the explicit absolute `projectRoot`; Windows drive, UNC and POSIX roots; `node_modules`, `node:` and foreign paths collapse into one anonymous `external` placeholder), a function symbol only if it matches a conservative safe-symbol pattern, line/column; never arguments, locals, source text, absolute paths, URLs or queries. Sample times are engine-clock offsets, the report's clock domain is fresh and its uncertainty stays the uncalibrated maximum. `interval.achieved_us` is what the engine delivered, `sample_gap` losses are counted from observed deltas, `truncated` losses are counted when a cap drops samples. `eventLoopDelay:true` adds a separate non-profile `event_loop_delay` measurement (signal `metric`, nanoseconds of loop delay; never mixed into samples). V8 allows independent inspector profilers, so a foreign profiler in the same isolate does not break this one; only the SDK's own process-global lease (`Symbol.for("soundpost.profile.owner.runtime_engine_samples")`, shared by duplicate module copies) is exclusive.

`report.ack` is `{status:"not_available", reason:"no_profile_admission_path"}`: the core client has no capability/profile record admission input, and the Go validator accepts only `runtime_cpu|native_cpu|native_offcpu` profile methods, so a report is returned to the caller but is not exported through C03 yet (nothing is fabricated). Real-runtime rows: `node fixtures/sdk/profiles/node.mjs` (compiles the module with the pinned Bun, runs on the actual Node, prints one evidence line, exits 0 only if every assertion holds). Node worker threads profile only their own isolate and report `scope.isolate:"worker"`. Node 24, other OS/CPU rows and the original manifest patch levels are NOT qualified by this evidence.
