# Changelog

## 0.1.0 — 2026-11-03

- Expose policy-first error graphs and explicit non-destructive global error/rejection listener leases.
- Use only available intrinsic native error brands and native event descriptors; retain explicit original-frame/aggregate-boundary limitations.
- Bind pending episodes to weak error identity and event source; actual browser fixture now covers unrelated rejection interleaving before error rethrow.
- Add cookie-free source-header HTTPS delivery with exact durable/historical receipt validation and bounded flush; prohibit disk spools and unread page-exit ACKs.
- Add explicit synchronous-only browser context, native spans, navigation commit timing, allowlisted fetch and closed worker propagation without guessed async parents.
- Add actual browser→Express→HTTP→PostgreSQL fixtures and exact driver/build checks; real Safari is not replaced by Playwright WebKit.
- Add manual job attempts with synchronous-only actual context and explicit terminal/error rebinding across await; author overlapping-job/real-browser C03/C05 fixtures without ambient-link or scheduler-health fiction.
- Add the owned replay recorder (`src/replay/`): capture only when project policy, deployment opt-in and explicit consent are all true; traverse the DOM directly into closed structural `ReplayNode`s (constant `"[masked]"` text/input masks, 8 CSS px quantized rectangles, inert tag enum, opaque frames/editable/textarea/select/media, 20,000-node cap with gap); `Client.startReplay`/`setReplayConsent` delegate to it and revocation destroys pending replay state without touching other queue entries.
- Hash the chain over canonical sorted-key JSON (`canonicalJSON`) instead of insertion-order `JSON.stringify`, so the hash equals Go's `replays.ChunkHash`.
- Emit every snapshot/delta as exactly one chunk: oversized content now collapses whole low-priority subtrees to opaque placeholders (`fitSubtrees`), reports the truncation (loss, `gap` event, gap-marked checkpoint) and suppresses deltas under the replaced ids until the next complete checkpoint; the continuation-chunk (fragmented checkpoint) behavior is removed.
- Add the optional JS Self-Profiling supplement `startProfile(options): Promise<ProfileHandle>` / `ProfileHandle.stop(): Promise<ProfileReport>` (`src/profile.ts`, method `browser_js_self_profile`): off unless started, feature-detected by constructing the real `Profiler` (never by version), one process-global lease (`profiler_owned`), bounded duration/buffer/stop, honest capability status+reason with zero samples for Firefox/Safari (`js_self_profiling_unavailable`), a missing `Document-Policy: js-profiling` header (`document_policy_missing`), scope mismatch and bad options; frames are leaf-first, origin-relative scripts or an `external` placeholder, never URLs with query/fragment; achieved interval, `sample_gap` loss (throttling/visibility) and separate non-profile `long_task` entries; no CPU unit. Real Chrome 156 qualification: `fixtures/sdk/profiles/browser.spec.ts`.
- Deliver profiles through the client queue: `client.startProfile(options)` / `client.submitProfile(report)` enqueue one `capability` record per run (refusals included, never a fabricated chunk) plus bounded, split `profile_chunk` records for a genuinely sampled run, via `src/profile_wire.ts`. Off unless `deploymentProfiles: true`; `createProfiler(env, deliver?)` gains the delivery sink. Module-level `startProfile` is unchanged (local report only).
