# Policy-first capture

Copyright 2026 Aryn Yklas. SPDX-License-Identifier: Apache-2.0.

This package implements policy-first safe capture, explicit Python spans/protocol adapters, explicit manual job-attempt observations (`client.job_attempt`) and bounded native HTTPS delivery. Replay recording and a Celery (or any other job-framework) adapter are not implemented; profiling exists only as the optional internal `soundpost.profile` adapter described below. No record is acknowledged merely by entering the queue. `buffered_records()` returns immutable serialized safe snapshots, never raw exceptions. `flush(timeout=2.0)` releases only matching durable receipts; `close()` flushes, releases owned hooks/transport/spool leases, and counts nondisk pending destruction as loss without claiming an ACK.

## Installation trust and policy protocol

The installation supplies trusted Ed25519 public keys by key ID. Policy envelope fields are `version: 1`, `algorithm: "Ed25519"`, `key_id`, `payload`, `signature`. The last two are unpadded canonical base64url. Signature verification covers decoded exact payload UTF-8 bytes and happens before parsing policy fields. The decoded payload must equal canonical JSON: sorted object keys, compact separators, UTF-8, no duplicates, no floating/nonfinite numbers. Required policy fields are `version`, `org`, `project`, `source`, `revision`, `expires_ns`, `errors`, `logs`, `replay`, `bodies`; optional strict boolean `traces`/`jobs` are false when absent from earlier signed documents. Deployment flags intersect the actual signed bit, never the errors permission. Revisions and nanoseconds are decimal strings. Bindings must match Config. Unknown keys and algorithms reject initialization. Expiration disables capture at admission, not only initialization. Trust is installation-owned, never downloaded from the signed envelope itself.

The deployment allowlist intersects policy booleans. Raw bodies are never an available capture input, even when both policy permissions allow them. Replay permission is only a decision value, not a recorder. Templates and approved resource identities are deployment registrations; signed policy alone cannot register arbitrary content. Service/environment/build use canonical nonzero opaque IDs, never human aliases. Approved field values are exact finite primitive enums, not arbitrary strings. Unknown fields are discarded without reading their values. Template revisions must increase; buffered lines and template revisions never change.

Every template registration explicitly supplies severity from `trace | debug | info | warn | error | fatal`; it is immutable per revision and preserved in the record. Text bounds count strict UTF-8 bytes in both SDKs: template line 4096, approved string field 256. Unpaired Unicode surrogates reject rather than silently replacing text. Config org/project/source/build identities are canonical nonzero 32-character lowercase hex IDs, never deployment display aliases. Verified policy org/project/source IDs must match those exact IDs. Policy/template revisions are canonical uint64 decimal strings (0 through 18446744073709551615); expiry and observed_at_ns are canonical signed int64 UnixNano strings (-9223372036854775808 through 9223372036854775807), including negative timestamps and rejecting -0/leading zeros. Past expiry is a policy-expired admission outcome, not overflow. Invalid/throwing injected clocks drop capture with only an invalid_clock counter; capture does not echo values or propagate clock exceptions.

## Record mirror

The SDK-local safe JSON record has `kind` (`error`, `log`, or `span`), `id` (32 lowercase hex), `observed_at_ns` (exact decimal string), `policy_revision` (decimal string), and `payload`. Error payload: `occurrence_id`, `exception_class`, `code`, `build_id`, `handled`, `fatal`, `mechanism`, root `frames`, `exception_graph` (`nodes`, `edges`, `reasons`), and optional validated trace/span links. Intrinsic BaseException descriptors preserve explicit cause, unsuppressed context, suppression flags, group ordinals, shared children and cycles without invoking exception getters/str/repr. The graph is bounded to 16 nodes and 128 inspected traceback frames; overflow/filtering reasons are explicit. No messages, arguments, values, locals or source contents enter records. Native C04 spans carry closed typed identities, clocks, statuses, aliases, links and exact probability bits, never raw attributes. Queue limits remain 1024 records/2 MiB UTF-8, 256 KiB per record, five-minute pending age.

## Safe frames, episodes and hooks

Set `Config(project_root=<absolute trusted application root>, ...)` to enable Python project-relative traceback identities. Only intrinsic traceback/frame/code fields are read; no source files, locals or globals are accessed. Frames include relative artifact/module ID, bounded function symbol, positive line, unknown column (`None`), in-app and async flags. Paths outside the lexical project root or unsafe identity syntax are omitted with `frame_not_project_safe`; no configured root reports `project_root_unconfigured`. No absolute home path is buffered.

`client.begin_handling_episode()` creates an explicit single-logical-occurrence token. `episode.capture_exception(error, code=...)` returns the same ID within that episode; `episode.close()` is idempotent and prevents further use. Create a new episode for every new logical error, even when the application reuses an exception instance. Python BaseException is not generally weakrefable: tokens retain neither raw errors nor object IDs, do not mutate user exceptions, and never infer identity from reused IDs. Temporary traversal references are explicitly cleared before extraction returns, including recursive-closure storage.

`from soundpost.hooks import install_hooks`; `lease = install_hooks(client, loop=optional_live_loop)` installs sys/threading handlers and an explicitly supplied or current running asyncio loop handler. A client owns at most eight open leases; close releases its own leases. Prior handlers are called unchanged after capture; default asyncio handling is delegated when no prior handler exists. Hooks are restored only if still owned, so subsequent application replacements survive. Overlapping leases become inert when closed; they never resume capture if a later lease restores their wrapper.

`lease.use_episode(episode, error=error, mechanism="uncaught_exception")` binds a weakrefable exception to the exact current Thread object and mechanism. Nonweak BaseException instances reject association unless the adapter explicitly supplies `explicit_rethrow=True`, acknowledging a same-thread/source immediate logical rethrow rather than claiming proven exception identity. Never use that opt-in for unrelated same-source callbacks; new logical handling needs a new token. `mechanism="thread_exception"` targets that thread's threading path. `mechanism="asyncio_exception", task=task` additionally requires this lease's exact loop and native asyncio Task and binds both weakly; missing/dead/mismatched tasks do not match. Unrelated threads/mechanisms/loops/tasks/errors capture independently and do not consume an arm. Up to eight arms are allowed; ambiguous nonweak same-source context arms reject. `lease.clear_episode(episode)` cancels pending associations; close clears them. No raw exceptions, numeric IDs or error mutations are retained. First-observation handled/fatal/mechanism stays immutable on reuse. Message-only/None-exception asyncio diagnostics increment `asyncio_missing_exception` without creating error occurrences; original prior/default handling still runs.

Shared C04 mechanisms are `manual | uncaught_exception | unhandled_rejection | thread_exception | asyncio_exception`; edge kinds are `cause | context | group` in both SDK schemas. Python None/JS nullish causes mean no edge. `fatal=True` means a process-level default-fatal observation (Python sys hook/Node monitor), not confirmed exit; prior application handlers remain authoritative. Python threading/asyncio and browser events use fatal=False because thread/task/browser reporting does not establish process termination.

## Native resource, routing and delivery

Config requires `resource=Resource(service_id, environment_id, build_id, instance_pseudonym, labels=())`. Obtain typed IDs and the approved opaque instance string from the real source registry; `resource.build_id` must equal Config.build. Resource labels are sorted unique `(name,value)` pairs and serialize to native `{name,value}[]`. Optional `RoutingDescriptor(version,org,project,source,routing_version,slots,policy_revision)` consumes the actual server descriptor and must match the verified policy/Config. Otherwise the SDK constructs the public fixed64 descriptor from those already-bound identities; it never creates authorization from a body.

Native batches partition normalized records by exact C03 owner slot **before** allocating immutable batch IDs/bytes/hashes. All ten owner kinds implement UTF-8 uint32-length-delimited SHA-256 fixed64 routing; metric routing excludes source/producer. Native canonical JSON, labels, integer histogram decimal strings and current C04 mechanism/graph vocabulary match Go. The shared owner/native-input goldens include Unicode and count/timestamp9007199254740993.

Queue limits are2MiB/1024 records/5minutes; native records cap at256KiB and ordered batches split at512 records/1MiB HTTP bytes (below4MiB expanded). Unfrozen timing/replay/profile work yields to critical errors/control; frozen unacknowledged work is protected. Loss diagnostics expose fixed reasons/counts, never dropped content. One client serializes exporter work so a producer/slot lane never overlaps.

HTTPS private-source transport uses `http.client` without a cookie jar, redirects, ambient proxy credentials or TLS bypass. Configure `ca_file` for an installation CA when needed; hostname/certificate verification stays on. Endpoint must be HTTPS `/ingest/v1/batches` without userinfo/query/fragment. Python accepts private sources only; browser source headers belong to the browser package.

FlushReport additionally preserves `receipts`: original batch/hash/cursor, exact per-kind retention deadlines, their minimum and the dedup deadline. ACK means durable append only, never indexed/rule-processed. Invalid receipts cannot ACK;401/403 stops export, new-admission409/422 is terminal counted loss,429/503 honors bounded Retry-After, and ambiguous timeouts remain pending. Retrying an ambiguous batch first authenticates `/ingest/v1/receipts` with its original source/producer/slot/batch/hash. A matching historical receipt can release it after policy restriction/expiry/deletion without new normalization/reservation/append. Only not-found allows reconsidering admission; changed/expired policy drops uncommitted work explicitly instead of mutating frozen bytes. Revoked/retired scope denies.

## Explicit encrypted backend spool

Default operation writes **no disk queue**. Opt in with `from soundpost.spool import EncryptedSpool`, construct `EncryptedSpool(path, protected_32_byte_key, descriptor, policy_revision, max_bytes=2097152)`, and pass it as `Config.spool`. AES-256-GCM authenticates typed scope/routing/policy headers; no payload or source credential is plaintext. Authenticated older-policy frozen state may recover only through historical lookup; a newer policy never makes old frozen bytes a new write.

The spool caps bytes, owns an exclusive OS advisory lock, writes encrypted temporary files with mode0600, fsyncs before atomic replacement, and syncs parent directories on supported POSIX filesystems. Corruption/authentication, competing leases and full/disk failures stay explicit and cannot manufacture receipts. Capture persists opt-in pending input; flush persists possible-send identity **before** network. Close retains encrypted pending work and releases leases. This is process-restart behavior, not device/power-loss/Windows namespace or kill-proof qualification. Protected key provisioning and the real runtime/filesystem matrix remain parent/deployment-owned.

Parent delivery commands: `python -m pytest sdk/python/tests/test_delivery.py -q`; `python fixtures/sdk/delivery/backend.py --config <private-real-Go-config.json> --lost-response`. The latter requires a real appcore-onboarded source, server-signed policy/resources and installation CA; it does not start a mock server or bypass TLS.

Spans inherit trace IDs and produce fresh span IDs, same-domain clocks and explicit cancellation/error/incomplete states. Sampling omission keeps local diagnostics but emits native C04 `Loss` (`signal=span`, `reason=policy`) only through the delivery owner's bounded producer/epoch/last-ACK aggregation and immutable receipt-aware queue. Expired, disabled, closed or exporter contexts cannot grant loss capture. Local counters are not a substitute for admitted native loss evidence.

## Trace clocks and uncertainty

`Config.clock_ns` supplies canonical signed-int64 wall nanoseconds for both record observation times and span wall stamps; default is local `time.time_ns()`. Span monotonic stamps always use actual local `time.monotonic_ns()` and the client's explicit clock domain. `Config.clock_uncertainty_ns` is a canonical uint64 decimal string; default `18446744073709551615` means uncalibrated/full wall range, not zero uncertainty or measured UTC accuracy. Supply a smaller bound only from trusted deployment calibration. Cross-domain causal links do not establish clock ordering/overlap; consumers must clamp uncertainty intervals to representable wall endpoints. Invalid configured wall clocks count explicit loss, omit malformed spans and preserve application exception/context semantics.

## Native loss delivery accounting

Queue `record_signal_loss(signal, reason, count:int, at_ns:str) -> bool` reports bounded aggregation acceptance, **not ACK**. The queue charges512-byte buckets inside its2MiB budget and owns producer epoch, exact count/interval, current nullable last-ACK cursor and queue usage. Reports use ordinary frozen native delivery and authenticated historical receipt lookup. Only a matching durable receipt increments acknowledged; expired/terminal/nondisk-close counts remain unexported and are never blindly reappended after possible commitment. Queue `signal_loss_counters()` returns exact-string observed/acknowledged/pending/unexported counts. Expected accepted sampling omission does not increment unexpected `FlushReport.lost`; capacity/recovery failures remain visible. Cold encrypted recovery may reject new aggregation until producer state is known and report `native_loss_recovery_pending`, never manufacture source/epoch. This SDK loss report is distinct from native profiler loss metadata.

## Error code authorization

An error `code` is authorized by the signed source policy's independent error-code registry (Go `SourcePolicy.Codes`), **not** by the span operation registry (`SourcePolicy.Operations`); the backend rejects a record whose `code` is outside `Codes`. Provision both registries separately. The SDK never widens a code: `capture_exception(error, code=...)` and episode captures keep a `code` only if it is in the client-side registered set (currently populated from `Config.operations`, so keep it in step with the signed `Codes`); any other value is exported as `code: null` and the record is still delivered. The SDK does not currently emit a dedicated counter for such a dropped code, so a mismatch between the SDK registry and the signed `Codes` is only visible as missing codes in the received data.

## Optional runtime supplements: `soundpost.profile` (internal adapter, not public C09)

`from soundpost.profile import ProfileOptions, start_profile`; `lease = start_profile(ProfileOptions(method=..., duration_s=..., project_root=...), client)`; `report = lease.stop()`. `start_profile` is an optional, explicitly started internal adapter, **not** an additional reviewed C09 API and not exported from `soundpost/__init__.py`. Profiling is off until called, hard-capped at 60 s, and never raises into the application for expected failures: invalid options return a report with capability `denied`/`invalid_options`, a second start returns `denied`/`profiler_owned` (one lease per process, held in a registry under a well-known key on `sys` so duplicate module copies still conflict), a closed client or a full hook-lease table returns `denied`/`client_unavailable`. The lease is registered with `client._own_hook_lease`, so `client.close()` stops it; `stop()`/`close()` are idempotent, bounded and always release the runtime facility, the lease slot and every thread/timer. A daemon timer stops the profile after `duration_s` (`stopped_by: "duration"`).

`ProfileOptions` (frozen): `method` (`python_monitoring` or `python_wall_samples`), `duration_s` (required, `0 < d <= 60`), `interval_ms` (wall sampling, default 10, 1..1000), `project_root` (absolute, same normalization as `Config.project_root`; defaults to the client's configured root; required for `python_monitoring`), `max_samples` (<=8192), `max_events` (distinct event rows, <=16384), `max_code_objects` (<=4096).

- `python_monitoring`: deterministic `sys.monitoring` events `PY_START`, `PY_RESUME`, `PY_RETURN`, `PY_UNWIND` counted per project code object (`events:[{frame, kind, count}]`, units `events`, `time_delta_unit: null`, no stacks/samples). The first free tool ID of `PROFILER_ID`(2), 3, 4 is used; if all are occupied the result is `denied`/`monitoring_tool_ids_occupied`; tools on other IDs keep their own callbacks and events untouched. Callbacks read only the code object (never the return value, exception, arguments or locals). Code outside `project_root` is disabled per location with `sys.monitoring.DISABLE`; because CPython remembers that per location, stop calls `sys.monitoring.restart_events()` so later profiles (and other tools) are not left blind (other tools simply see those locations fire once again). Beyond `max_code_objects` distinct code objects (or `max_events` rows) further ones are dropped, their locations disabled and reported as a `truncated` loss (`scope.dropped` carries the code-object/row breakdown).
- `python_wall_samples`: a daemon sampler thread calls `sys._current_frames()` every `interval_ms`, skips its own thread and the lease timer, walks `f_back` at most 128 frames (leaf first; `scope.stacks_truncated` counts deeper stacks) and never touches `f_locals`/`f_globals`. Samples are `{at_us, stack, count: "1", thread}` with `at_us` in wall microseconds since report start (`units: "samples"`, `time_delta_unit: "wall_microseconds"`); `thread` is an ordinal, never a thread name. The achieved mean gap is `interval.achieved_us`; the max gap and tick count are in `scope.sampler`; gaps above 2x the requested interval produce a `sample_gap` loss whose count is the derived number of missed ticks. Coverage is `frames: partial` (Python frames only; native C frames and time in native code are attributed to the calling Python frame; nothing is symbolized natively), `threads: partial` (a thread is sampled only when the sampler acquires the GIL, so GIL-held spans are biased and GIL wait is invisible), `workers: none` (other interpreters/processes), `tasks: none` (a suspended asyncio task has no thread stack and is never sampled; no suspended-task ancestry is invented). The same facts are machine-readable in `scope.bias`: `{gil_acquisition, native_time_attributed_to_python_caller, suspended_tasks_unobserved}`, all `true`. On Windows the OS timer granularity and GIL contention are visible as a larger achieved interval and `sample_gap` loss, not hidden.

No OS CPU unit is ever assigned: units are `samples`/`events` plus `wall_microseconds` offsets. Frames are code identities only: project-relative path, function qualname only if it matches a conservative symbol pattern (otherwise empty with reason `not_captured`), everything outside the root collapses to one `external` placeholder frame (consecutive duplicates collapsed). Absolute paths, argument/local values, thread names and exception values never appear. Free-threaded builds report `unsupported`/`free_threaded_unqualified`; a missing `sys.monitoring` reports `unsupported`/`sys_monitoring_unavailable`; unsupported/denied results carry zero frames/samples/events.

Capability: the report's `capability` is the closed C04 field set (`id`, runtime/version/build/os/arch, `signal: "profile_chunk"`, method, status, reason, coverage, a fresh three-ID `clock_domain`, `expires_ns` one hour after start); `soundpost.wire` accepts it as a `capability` record (record `id` = capability `id`, remaining fields as payload). With the signed `loss` permission, `truncated` and `unsupported` results are also reported through `client._record_signal_loss("profile_chunk", reason, count)`; `ack.status` is `obtained` with `cursors` only when `client.flush()` actually returns acknowledged cursors, otherwise `failed` (reason `no_acknowledged_cursor`/`flush_deadline_exceeded`/`flush_error`) or `not_available` (`no_loss_recorded`, `loss_not_admitted`). The C04 `profile_chunk` method set in the Go validator does not yet include the Python methods, so no profile chunk is exported; only the capability and loss records are.

Results are runtime evidence for the executing interpreter only, not qualification of other interpreters or operating systems.
